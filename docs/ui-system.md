# 공통 UI 스타일

`src/components/ui/primitives.tsx`의 버튼, 카드, 탭, 입력란과 공통 모달·선택 메뉴를 사용합니다. 색, 글자 크기, 모서리, 간격, 쌓임 순서는 `src/styles/tokens.css`에서 정의하고, UI 기본 요소의 공통 상태는 `src/styles/terminal-system.css`, 화면별 스타일은 해당 화면의 파일에서 적용합니다. 파일 구성과 적용 순서는 [CSS 구조와 측정](#css-구조와-측정--2026-11-07)을 참고합니다.

- 본문은 기본 16px, 보조 설명은 14px, 캡션은 13px입니다. 코드와 로고 외의 설명은 산세리프 글꼴을 사용합니다.
- 버튼과 선택 항목의 기본 조작 높이는 44px입니다. 카드 모서리는 22px, 버튼과 입력란은 12px입니다.
- 다크 배경과 패널은 밝기로 구분합니다. 파란색은 주요 행동과 선택, 초록색은 성공, 경고색은 확인이 필요한 상태에 사용합니다. 색과 함께 문구나 아이콘으로 상태를 표시합니다.
- 배너 이미지는 가용 너비에 비례해 표시합니다. 모바일에서는 본문 아래에 배치합니다. 장식 이미지의 가장자리만 마스크로 혼합하며 프로젝트 근거 스크린샷에는 적용하지 않습니다.
- 키보드 초점 표시와 동작 감소 설정을 유지합니다. 설명 글자는 줄바꿈을 허용하며 고정 높이로 자르지 않습니다.

## 진입 화면과 모바일 메뉴

- 홈은 프로젝트 점검 배너를 먼저 보여줍니다. 타입 선택은 처음 방문한 경우에만 배너 아래에 표시하며, 기록이 없는 사용자에게 별도의 동일한 프로젝트 안내 카드를 반복하지 않습니다.
- 저장된 프로젝트가 있으면 제목과 이어하기 링크를 간결한 카드로 표시합니다. 기록 조회에 실패하면 재확인 링크를 표시합니다.
- 1024px 미만의 메뉴는 공통 모달에서 열립니다. 사이드바와 같은 메뉴, 현재 이용 상태와 환경 설정을 담고 현재 위치를 표시합니다. Escape나 ‘메뉴 닫기’로 닫으면 메뉴 버튼으로 초점이 돌아옵니다. 작업 공간 변경은 헤더에 있습니다.
- 새 프로젝트의 입력 화면에서는 비어 있는 기록 목록을 생략합니다. 이용 횟수와 분석 가능 상태는 폼 위에, 로그인 혜택은 폼 아래에 표시합니다.
- 모바일 배너는 시작 버튼을 이미지보다 먼저 보여줍니다. 프로젝트 점검의 장식 이미지는 모바일에서 생략해 입력 공간을 확보합니다.

## 앱 셸 — 2026-11-07

모든 경로가 루트 레이아웃의 `AppShell`(`src/components/shell/app-shell.tsx`) 안에서 렌더링됩니다. 이전에는 홈과 문제 풀이가 `PracticeApp`의 사이드바와 헤더를, 나머지 9개 경로가 `DesktopFrame`과 페이지마다 `<main>` 안에 넣은 `SiteHeader`를 써서 메뉴, 로그인 상태, 환경 설정, 중단점(760px와 1024px)이 경로마다 달랐습니다.

- 순서: 본문으로 이동 링크 → 사이드바(`aside` ‘주 메뉴’: 작업 공간 메뉴, 현재 이용 상태, 환경 설정) → 헤더(`header.app-header`: 메뉴 열기, ‘현재 위치’ 이동 경로, 작업 공간 변경, 테마, 사용 안내, 화면별 버튼) → 연결 상태 안내 → 페이지의 `<main id="main-content">` → 바닥글(짧은 안내, 개인정보 안내). 헤더는 `<main>` 밖에 있으며, 본문으로 이동 링크는 `<main>`에 `tabindex="-1"`을 두고 초점을 옮깁니다.
- 중단점은 1024px 하나입니다. 1024px 이상은 240px 사이드바를, 미만은 헤더의 ‘메뉴 열기’(`aria-expanded`, `aria-haspopup="dialog"`)가 같은 내용을 공통 모달로 엽니다. 창을 1024px 이상으로 넓히면 메뉴 대화상자를 닫습니다.
- 현재 이용 상태는 루트 레이아웃이 서버 세션을 읽어 스트리밍합니다. 로그인하면 이름과 ‘내 프로필’, 로그인 전에는 ‘로그인 / 가입’(현재 경로로 돌아오는 `returnTo` 포함)을 표시합니다.
- 메뉴는 나의 연습실(홈, 내 프로젝트), 내 서비스 점검(내 프로젝트 점검, 서비스 보안 점검), AI 활용(AI 실무 배우기, 내 프로젝트 AI 워크숍), 코드와 원리(AI 코드 이해 훈련, 분야별 코딩 연습, 서비스 원리 배우기), 내 기록(북마크, 내 학습 기록)으로 묶습니다. 현재 화면인 항목에만 `aria-current="page"`를, 수업·미션·문제처럼 하위 화면에서는 상위 항목에 `aria-current="true"`를 붙입니다. 규칙은 `src/lib/shell-location.ts`의 `navCurrent`입니다.
- 이동 경로는 `<nav aria-label="현재 위치"><ol>` 구조입니다. 마지막 항목에 `aria-current="page"`를 붙이고 구분선 `/`은 `aria-hidden`입니다. 이름은 `locationTrail`이 경로와 검색 매개변수로 정합니다. 알 수 없는 경로는 ‘페이지를 찾을 수 없음’으로 표시합니다. 760px 이하에서는 로고만 표시합니다.
- 코딩 홈과 문제 풀이(`PracticeApp`)는 `HeaderActions`로 새로고침과 AI 문제 생성 버튼을 헤더에 더합니다. 760px 이하에서는 두 버튼을 ‘빠른 작업’ 대화상자로 모읍니다. 문제 풀이의 집중 모드는 `useFocusMode`로 사이드바를 숨깁니다.
- 홈의 보기 전환(홈, 북마크, 내 학습 기록, 분야별 코딩 연습, 분야)은 `PracticeApp`을 다시 마운트하지 않습니다. 불러온 작업 공간 데이터를 유지하고 목록만 새로 받습니다. 작업 공간 데이터는 계속 클라이언트에서 `/api/workspace`로 불러옵니다.
- 고정 위젯 여백: `--floating-safe-area`(기본 88px, 시작 가이드가 없는 문제 풀이 화면은 0px)만큼 바닥글 아래와 휴대폰 알림 위치를 띄웁니다.
- 루트 `not-found.tsx`(홈, 내 프로젝트, 이전 페이지), `error.tsx`(Next 16의 `retry`로 다시 시도), `global-error.tsx`(자체 `<html>`·`<body>`, 저장된 테마 적용)를 제공합니다. 404와 페이지 오류는 셸 안에 표시됩니다. `/learn/[id]`의 `notFound()`도 루트 404 화면을 씁니다.
- 각 `loading.tsx`는 `RouteLoading`으로 본문 영역만 채우고 헤더와 메뉴는 그대로 둡니다. 홈(`/`)은 `loading.tsx` 없이 이전 화면을 유지한 뒤 바뀝니다.

### 공통 피드백

- 알림: 루트 `ToastProvider`(`src/components/ui/toast.tsx`)의 `useToast().show(message, tone)`. 성공 알림은 4.5초 뒤 사라지고 오류 알림은 닫을 때까지 남습니다. 성공은 `role="status"`, 오류는 `role="alert"` 영역에 추가하며 두 영역은 항상 마운트되어 있습니다. 위치는 `--shell-sidebar-width`를 기준으로 본문 가운데입니다.
- 진행 막대: `api()`의 추적 요청이 400ms 넘게 대기할 때만 표시합니다. 자동 저장, 폴링과 배경 새로고침은 `track: false`로 제외합니다. 화면에 보이지 않는 polite 영역 하나가 긴 대기의 시작과, 그 대기가 실패로 끝난 경우만 알립니다. 호출한 화면이 취소한 요청은 실패로 세지 않습니다.
- 네트워크 오류: `errorMessage()`는 브라우저 원문(Failed to fetch, Load failed, NetworkError…)을 한국어 안내로 바꾸고, 오프라인이면 ‘인터넷 연결이 끊겼습니다’ 안내를 씁니다. 헤더 아래 연결 상태 안내는 연결이 끊긴 동안 표시하고, 다시 연결되면 4초간 알립니다.
- 대화상자: `Modal`은 제목을 `h2`로 렌더링하고 `aria-labelledby`로 연결합니다. Tab과 Shift+Tab은 대화상자 안에서 순환합니다. 닫기 버튼 이름은 `closeLabel`로 바꿀 수 있습니다.
- 키보드: 입력 중이 아닐 때 `?`는 사용 안내를, `/`는 분야별 코딩 연습의 문제 검색을 엽니다. 둘 다 IME 조합 중에는 동작하지 않습니다. 사용 안내는 편집기의 ⌘/Ctrl+Enter(AI 풀이 검토), ⌘/Ctrl+S(지금 저장), Ctrl+M(Tab 초점 이동 전환, macOS는 Ctrl+Shift+M), Alt+F1(접근성 도움말)도 안내합니다.
- 메타데이터: 루트 제목 템플릿은 `%s | CODE:FIT`(`src/lib/site.ts`)이며 페이지는 자기 이름만 정합니다. 내장 문제는 `/problems/[id]` 제목에 문제 이름을 씁니다. `metadataBase`는 `APP_ORIGIN`, `AUTH_BASE_URL`, `VERCEL_PROJECT_PRODUCTION_URL` 순서로 정합니다. `sitemap.xml`은 공개 경로, AI 수업, 미션과 내장 문제를, `robots.txt`는 `/api/`와 `/profile` 제외를 담습니다.

전역 CSS는 여전히 `src/app/globals.css` 하나가 모든 경로에 불러온다. 이번 정리는 화면을 바꾸지 않는 범위에서 죽은 규칙 제거, 적용 순서 명시, 토큰화, 글꼴·이미지·캐시 설정을 다룬다.

### 적용 순서

`globals.css`는 `@layer tokens, base, components;`를 선언하고 각 파일을 `@import "…" layer(…)`로 불러온다. 뒤 레이어는 선택자 우선순위와 관계없이 앞 레이어를 이긴다.

| 레이어       | 파일                                    | 내용                                                                                                                                                                                                      |
| ------------ | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tokens`     | `tokens.css`                            | 공유 사용자 정의 속성만 둔다: 색 역할, 간격·모서리·쌓임 순서, 글꼴, 셸 크기, 범위가 정해진 역할 재정의(학습 화면의 `--surface`, 실습 화면의 `--text`/`--muted`). 미디어 쿼리 중단점 목록도 주석으로 둔다. |
| `base`       | `base.css`                              | 요소 선택자만 쓰는 초기화, 글자·입력란 기본값, 유일한 초점 윤곽선 정의, keyframes.                                                                                                                        |
| `components` | `foundation.css` … `desktop-layout.css` | 나머지 39개 파일. 레이어 안에서는 import 순서대로 뒤 파일이 앞 파일을 덮는다. `terminal-system.css`는 UI 기본 요소(`.ui-*`)와 변형의 공통 상태를 담고 화면 파일 뒤에 온다.                                |

레이어가 없는 CSS는 모든 레이어보다 우선한다. Monaco가 실행 중에 넣는 `editor.main.css`와 next/font의 `@font-face`가 여기에 해당한다. 프로젝트 CSS에는 Monaco 내부 클래스를 겨냥한 선택자가 없고, Monaco CSS는 `:root`의 `--vscode-*` 변수 외에는 `.monaco-*` 등 자체 클래스만 쓴다. 인라인 `style`은 레이어와 무관하게 이전과 같이 적용된다.

`button:disabled`와 상호작용 전환(`button:not(:disabled), a, input, …`) 규칙은 요소+가상 클래스 우선순위로 단일 클래스 규칙을 이겨 왔기 때문에 `base`가 아니라 `foundation.css`(components)에 둔다. 레이어를 나눈 뒤 우선순위가 뒤집히는 선언 쌍은 정적 분석으로 0건(가능성만 있는 `:root` 대 `.sample-app` 2건은 같은 요소가 될 수 없음)을 확인했다.

### 덮어쓰기 파일 정리

나중에 덧붙여 앞선 화면을 다시 꾸미던 `design-consistency.css`, `design-polish.css`, `design-clarity.css`, `palette.css`, `reading-rhythm.css`, `workspace-spacing.css`를 삭제하고 규칙을 해당 선택자를 소유한 파일로 옮겼다. `terminal-system.css`는 화면 하나에만 쓰이는 73개 규칙을 각 화면 파일로 옮기고 공통 상태 파일로 남겼다.

- 옮기는 위치는 같은 선택자의 기존 규칙(병합), 그 클래스를 가장 많이 쓰는 파일의 끝, 덮어쓰던 규칙의 바로 뒤 순으로 골랐다.
- 옮기기 전후 사이에 같은 우선순위, 관련 속성(단축·개별 속성 포함), 겹칠 수 있는 요소(정적 className 조합과 렌더링된 DOM의 클래스 조합으로 판단), 겹치는 미디어 조건을 가진 선언이 있으면 옮기지 않았다. 따라서 어떤 요소에서도 이기는 선언이 바뀌지 않는다.
- `.visual-intro.visual-intro`(2곳)는 같은 최종 값의 단일 클래스 규칙 하나로 합쳤다. 이중 클래스 선택자는 남아 있지 않다(이전 `.site-header.site-header` 7곳은 요소가 사라져 제거).
- 초점 윤곽선은 `base.css`에 한 번만 정의한다(`2px solid var(--action)`, 간격 4px). UI 기본 요소는 간격만 3px로 바꾼다. 이전에는 `foundation.css`, `palette.css`, `terminal-system.css`가 각각 윤곽선 색이나 전체 값을 다시 지정했다.

### 죽은 CSS

src(테스트 제외)의 어떤 TS/TSX에도 나오지 않는 클래스·id·`data-*` 속성을 요구하는 선택자 429개(규칙 370개)를 지웠다. 화면별 헤더(`SiteHeader`), `DesktopFrame`, 첫 방문 기능 슬라이드와 예전 홈 구역의 규칙이 대부분이다. 템플릿 문자열로 만드는 클래스(`kind-`, `level-`, `security-`, `service-`, `provider-`, `workspace-`, `skeleton-`, `is-`, `lab-stage-`)는 실제 값 목록과 대조해 남겼다. `:not()` 안의 클래스는 선택자를 무효로 만들지 않으므로 그대로 두었다. 쓰이지 않던 `--feature-enter-x`, `--feature-accent`, `--light-purple-soft`, `--light-cyan-soft`와 `@keyframes feature-enter`도 지웠다.

### 토큰

- 간격: `--space-1`(4px)부터 `--space-16`(64px)까지 4px 단위(1–8, 10, 12, 14, 16). 길이 값이 모두 이 척도에 맞는 margin/padding/gap 선언 1,162개를 바꿨다. 2·6·10·14·18px처럼 척도 밖의 값은 리터럴로 남는다.
- 모서리: `--radius-panel` 22px(카드·패널), `--radius-control` 12px(버튼·입력란), `--radius-small` 8px, `--radius-pill` 999px. 값 하나짜리 선언 73개를 바꿨다.
- 쌓임 순서: `--z-raised` 1, `--z-sticky` 10, `--z-header` 30, `--z-floating` 35(시작 가이드), `--z-drawer` 40(사이드바), `--z-floating-panel` 80(분석 진행 패널), `--z-overlay` 90, `--z-toast` 100(알림, 본문 이동 링크), `--z-progress` 120. 모바일 작업 막대만 5에서 `--z-sticky`(10)로 바뀌었다. 5와 10 사이의 다른 z-index가 없어 쌓임 순서는 같다. 모달 머리글의 2는 컴포넌트 안의 쌓임이라 리터럴로 둔다.
- 중단점: 셸은 1024px 하나(이상은 240px 사이드바), 760px은 헤더 축약. 화면별로 1000/1001, 900, 700, 650, 640, 600, 540, 480, 440, 420, 360px도 쓴다(목록은 `tokens.css` 주석). 미디어 쿼리는 사용자 정의 속성을 읽지 못한다.
- 색: 반복이 많은 `light-dark()` 쌍을 역할 토큰으로 바꿨다(159곳). 서비스 미션·샘플 화면의 `--sample-text`, `--sample-muted`, `--sample-line`, `--sample-strong-line`, `--sample-surface`, `--sample-surface-raised`, 그림 영역의 `--art-surface`, 작업 공간 구분선 `--editor-line`, 버튼 선 `--control-line`, 고정 카드 배경 `--panel`. 라이트 값이 이름과 반대였던 `--black`/`--white`는 `--surface-deep`/`--text-strong`으로 바꿨다. 라이트 테마의 컨테이너 선(`#d5dde8`)은 `--light-hairline` 토큰이 되었고 `--line`을 더 이상 다른 파일에서 다시 정의하지 않는다.
- 순수 회색 다크 값(R=G=B) 148종 290곳은 그대로 두었다. 다크 표면·선·글자 토큰과의 CIEDE2000 차이가 가장 작은 값도 2.59(`#f3f3f3`→`--text`)이고, `#242424`(7.16), `#353535`(9.26), `#444444`(9.12)처럼 많이 쓰는 회색은 더 멀어 구분 없이 바꿀 수 있는 값이 없었다.

### 글꼴

Google Fonts CSS `@import`(foundation.css 첫 줄)를 없애고 `next/font/google`(`src/app/fonts.ts`)으로 빌드 때 내려받아 같은 출처에서 제공한다. `display: swap`, latin 범위만 미리 불러온다. 글꼴 변수는 `<html>`(루트 레이아웃과 `global-error.tsx`)에 붙고 `--sans`/`--mono`가 이를 읽는다.

- Noto Sans KR: 가변 글꼴. CSS가 쓰는 굵기는 400, 450, 500, 550, 600, 650, 700, 800이고 450/550/650은 가변 축으로만 정확히 그려진다. 이전 9개 굵기 요청도 범위별로 같은 가변 파일을 내려받았다. 한글 범위 파일은 쓰일 때만 불러온다.
- IBM Plex Mono: 정적 글꼴 400, 500, 600, 700(450 요청은 이전에도 400으로 그려졌다).
- 이전 요청 URL의 CSS 응답은 압축 전 857,413바이트(@font-face 1,136개)였다. 현재는 앱 CSS 안에 @font-face 146개(가변 Noto 124개 포함)가 들어간다.

### 이미지

GitHub SVG를 뺀 모든 로컬 이미지에서 `unoptimized`를 없앴다. 이미지 최적화기가 표시 크기에 맞는 WebP를 만든다.

- `ThemedImage`: 다크 `<img>`는 `next/image`, 라이트 `<source>`는 같은 width·height·sizes로 `getImageProps()`가 만든 srcset을 쓴다. 반대 테마 미리 받기도 같은 srcset으로 요청한다.
- 상황 그림(1024px 2×2 아틀라스, 틀 너비의 2배로 그림): 단계 설명 `(max-width: 600px) 144px, 200px`, 코드 이해 카드 `410px`. 소개 그림 `(max-width: 700px) 228px, 320px`, 학습 유형 카드 `(max-width: 600px) 72px, (max-width: 1100px) 50vw, 360px`, 프로젝트 썸네일 `(max-width: 640px) 100vw, (max-width: 1023px) 50vw, 560px`.
- 30–34px로 보이는 256px 브랜드 아이콘, 32·76px로 보이는 256px 가이드 마스코트, 20px로 보이는 200px Google 아이콘도 1x/2x 크기로 제공된다(새 로고 파일은 만들지 않았다).
- `public/` 확인: `images/scenarios/total.webp`가 253KB로 다른 아틀라스(44–76KB)의 3–5배다. `images/features/*.webp` 4개와 `images/light/features/*.webp` 2개(약 160KB)는 기능 슬라이드 제거 후 앱 코드에서 쓰지 않는다. 라이트 2개는 `docs/light-artwork-prompts.json`과 `e2e/theme-artwork.spec.ts`의 자산 목록에 남아 있어 지우지 않았다.

계산된 스타일 비교: 같은 80개 화면의 모든 요소(::before/::after 포함)에서 80여 개 속성을 단계마다 비교했다. 차이는 모바일 작업 막대의 z-index 5→10, 아래 두 라벨의 font-weight 900→800(그려지는 굵기는 이전과 같음), next/font가 붙이는 대체 글꼴 이름(`"Noto Sans KR Fallback"` 등)뿐이다. 렌더링 시점에 따라 바뀌는 값(상황 그림의 auto 여백, 시작 가이드 위치, React id)은 같은 코드를 다시 캡처해 잡음임을 확인했다. 프로덕션 빌드(`npm start`)의 계산된 스타일도 개발 서버와 같았다(그라데이션 표기 `to right`→`90deg` 정규화만 다름).

가변 글꼴의 단일 @font-face(굵기 100–900)는 `bolder`로 계산된 900을 그대로 그린다. 이전 Google CSS는 요청한 굵기마다 @font-face를 두었고 가장 굵은 것이 800이라 900 요청을 800으로 그렸으므로, 캡처에서 발견한 두 곳(헤더 작업 공간 이름 `.persona-change strong`, 프로젝트 점검 단계 버튼 `.journey-options button strong`)은 `font-weight: 800`으로 이전 굵기를 유지했다. 확인하지 않은 화면 상태에서 굵기 550 이상인 글자 안의 `strong`/`b`는 800 대신 900으로 그려질 수 있다.

확인하지 않은 범위: 마우스 오버·초점·열린 대화상자 등 캡처하지 않은 상태는 위의 정적 cascade 검사로만 확인했다. Firefox·WebKit과 실제 운영 사이트, 로그인 상태와 저장된 프로젝트가 있는 화면은 이번에 캡처하지 않았다. Playwright e2e는 실행하지 않았다. `e2e/theme-artwork.spec.ts`, `e2e/theme-image-loading.spec.ts`는 최적화된 이미지 URL(`/_next/image?url=…`)에 맞춰 고쳤고, 같은 판정을 별도 스크립트로 프로덕션 서버에서 확인했다.
