# AI 실무 배우기

`/learn/ai`에서 AI 도구와 기술을 용도별로 찾고 학습한다. 홈, 서비스 원리 학습 화면, 공통 메뉴, 내 기록에서 진입할 수 있다.

## 내 프로젝트로 배우기

AI 워크숍 홈과 이 화면의 상단 GitHub 입력에서 내 프로젝트 AI 워크숍으로 이동한다. 기존 저장소 분석을 재사용할 수도 있다. 코드에서 사용 근거가 있는 AI와 새 적용 아이디어를 구분하고, 코드 인용, 관련 기본 수업, 실험 계획, 대안과 확인 기준, 이해 확인 문제를 제공한다. 학습 생성은 외부 AI API를 사용하며 저장한 답변과 적용 기록은 서버에 보관한다. 상세 범위와 한도는 [내 프로젝트 AI 워크숍](project-ai-workshop.md)을 참고한다.

아래 콘텐츠와 진도 설명은 기본 32개 수업에 해당한다. 화면의 분야·수업 수는 카탈로그 데이터에서 계산한다.

## 콘텐츠 범위

2026-09-21에 확인한 공식 문서와 공식 저장소를 바탕으로 15개 분야, 32개 수업을 제공한다. 각 수업은 독립적으로 시작할 수 있다.

## 목록 화면

- 기본 화면은 분야 목록이다. 각 분야는 수업 수와 완료한 수업 수를 보여 주고, 한 번에 한 분야만 펼친다. 펼친 분야는 주소의 `track` 값으로 남아 수업에서 돌아와도 같은 분야가 열리고 스크롤 위치를 복원한다.
- 기술명 검색이나 학습 수준을 고르면 분야 구분 없이 일치하는 수업을 한 목록으로 보여 준다. 랭체인, 랭그래프 등 한글 검색어를 지원한다. 결과 수는 입력이 멈춘 뒤에만 화면 낭독기에 알린다.
- 추천 학습 순서(처음이라면, 내 컴퓨터에서 써보고 싶다면, 내 문서로 답하는 AI를 만든다면)는 완료한 수업에 체크 표시와 `n/m 완료`를 보여 준다. 순서의 링크는 `?path=beginner|local|rag`를 붙여 연다.
- 확인 문제를 처음에 틀린 수업은 `다시 볼 수업` 목록에 모은다.

## 학습 동작

- 개념 이해 → 선택하며 실습 → 확인 문제로 진행한다.
- 실습 선택에 따른 모의 결과를 확인해야 확인 문제로 이동할 수 있다.
- 확인 문제의 정답을 제출해야 완료 처리한다. 해설은 정답을 맞혔거나 서로 다른 오답을 2번 고른 뒤에만 보여 준다. 이미 고른 오답에는 `이미 고른 오답` 표시를 붙이고, 같은 선택은 다시 채점하지 않는다.
- 처음 채점한 답의 정답 여부(`firstAttemptCorrect`)를 한 번만 기록한다. 확인 문제를 다시 풀어도 바뀌지 않는다.
- 다음 수업은 수업을 연 맥락 안에서 고른다. 추천 순서(`?path=`)에서는 그 순서의 다음 수업, 내 프로젝트 AI 워크숍 주제(`?lessons=`)에서는 그 주제에 연결된 다음 수업을 고르며, 주제의 마지막 수업 뒤에는 프로젝트로 돌아가기를 안내한다. 맥락이 없거나 추천 순서가 끝나면 같은 분야, 그다음 목록 순서로 넘어가며 완료하지 않은 수업을 먼저 고른다.
- 이전 단계 복습, 전체 목록 복귀를 제공한다.
- 외부 AI API 호출, 도구 설치, 터미널 명령 실행은 하지 않는다. Ollama 명령어는 학습자가 자신의 환경에서 사용할 수 있는 예시다.
- 키보드로 선택지를 조작할 수 있고 단계 이동 시 제목으로 초점을 이동한다. 선택 결과는 라이브 영역으로 안내한다.

## 선택지와 콘텐츠 버전

확인 문제와 실습 선택지는 ID로 저장한다. 확인 문제 선택지는 `extended-content.ts`의 `[ID, 문구]` 또는 `content.ts`의 `{ id, text }`로 적고, 실습 선택지는 ID를 생략하면 처음 공개된 순서의 글자(a, b, c)를 쓴다. 선택지 수는 2~4개를 허용한다.

수업마다 콘텐츠 버전(`aiContentVersion`)이 있다. 버전 1 기록은 선택지 위치를 저장했으므로 실습 선택은 같은 순서의 글자 ID로 옮기고, 2026-11 개편으로 다시 쓴 확인 문제의 선택은 복원하지 않는다. 완료 여부와 단계는 유지한다. 같은 ID의 선택지 뜻을 바꾸면 해당 수업의 버전을 올려 이전 선택이 답으로 표시되지 않게 한다.

`src/lib/ai-learning/choice-balance.test.ts`는 확인 문제와 서비스 원리 미션의 응용 문제에서 정답 문구가 다른 선택지보다 15% 넘게 길면 실패한다. 2026-11-07 개편 전에는 AI 수업 32개 중 31개, 현재 미션 21개 모두에서 정답이 유일하게 가장 긴 선택지였다.

## 기록 보관

수업별 단계, 실습 선택, 확인 문제의 선택·채점·오답, 첫 답변 정답 여부, 완료 여부, 콘텐츠 버전과 마지막 변경 시각을 서버의 학습 기록(`learning_progress`, 수업 ID `ai:<수업 ID>`)에 저장한다. 로그인 계정은 다른 기기에서도 이어서 보고, 게스트는 이 브라우저의 쿠키로 찾는다. 계정 백업에도 포함된다([학습 기록 백업과 복원](workspace-backup.md)).

`codefit.ai-learning.v1` 로컬 저장소는 빠르게 보여 주기 위한 캐시이며, 어느 계정(작업 공간 범위)의 기록인지 함께 저장한다. 화면을 열면 서버 기록을 받아 캐시와 합치고, 서버에 없는 내용만 올린다. 합칠 때는 완료와 첫 답변 오답을 어느 쪽에서도 잃지 않고, 현재 단계와 확인 문제 선택은 더 최근 기록을 따른다. 범위가 없는 이전 캐시는 처음 동기화한 계정으로 한 번 올리고, 다른 계정의 캐시는 올리지 않고 서버 기록으로 바꾼다. 저장은 0.6초 모아서 보내며, 화면을 닫을 때 남은 저장을 보낸다. 동기화 요청은 전역 진행 표시줄에 나타나지 않는다(`track: false`). 탭이 다시 보이거나 연결이 돌아오거나 백업을 가져오면 다시 동기화한다.

서버에 연결하지 못하면 이 브라우저에만 기록했다고 안내하고 다음 동기화 때 올린다. 브라우저 저장소를 쓸 수 없으면 메모리와 서버에 기록한다. 형식이 잘못된 기록, 알 수 없는 수업 ID, 범위를 벗어난 단계와 선택은 복원하지 않으며 서버는 이런 기록을 400으로 거절한다.

최근 진행한 미완료 수업부터 이어갈 수 있다. 진행 중인 수업이 없으면 `처음이라면` 순서에서 완료하지 않은 첫 수업을 권한다. 완료한 수업을 다시 열면 요약과 다음 수업을 먼저 보여주며, 해설을 펼쳐 보거나 확인 문제를 다시 풀 수 있다.

## 유지보수와 검증

- 카탈로그와 콘텐츠 버전: `src/lib/ai-learning/catalog.ts`
- 수업 내용과 출처: `src/lib/ai-learning/content.ts`, `extended-content.ts`
- 추천 순서와 다음 수업: `src/lib/ai-learning/lesson-paths.ts`
- 기록 형식·병합과 검색: `src/lib/ai-learning/progress.ts`, `src/hooks/use-ai-learning-progress.ts`
- 서버 저장: `src/app/api/learn/ai/route.ts`, `src/lib/server/ai-learning-progress.ts`
- 단위 검증: `npx vitest run src/lib/ai-learning src/lib/server/ai-learning-progress.test.ts`
- 브라우저 검증: `npx playwright test e2e/ai-learning.spec.ts e2e/ai-catalog-return.spec.ts --project=chromium`

브라우저 검증은 분야 목록과 검색, 모든 수업의 선택 및 완료, 새로고침 후 이어보기, 오답 뒤 해설 숨김, 다시 볼 수업, 모바일 화면 너비, 접근성, 저장소 차단과 잘못된 주소 복구를 포함한다. 실제 AI 도구의 설치나 외부 API 연동 결과는 이 검증 범위에 포함하지 않는다.
