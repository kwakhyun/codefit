# 공개 소스 저장소 연결

서비스 점검실, 프로젝트 기반 코드 훈련과 서비스 원리 실습, AI 워크숍에서 공개 저장소의 HTTPS 주소를 입력한다. 플레이스홀더는 익숙한 GitHub 예시를 보여주지만 다른 호스팅 플랫폼도 지원한다.

- GitHub 저장소와 PR은 기존 GitHub API 수집 경로를 사용한다.
- 다른 Git 호스팅은 격리된 Sandbox에서 HTTPS로 얕게 복제한다. 대상 코드를 실행하거나 의존성을 설치하지 않으며, 체크아웃과 서브모듈 다운로드도 하지 않는다.
- 알려진 호스팅 주소와 `.git` 주소는 자동 구분한다. 자체 호스팅 주소를 프로젝트 점검에 입력할 때는 주소 종류에서 공개 소스 저장소를 선택할 수 있다. 저장소 전용 입력창은 별도 선택 없이 처리한다.
- 인증 없는 HTTPS 복제가 가능해야 한다. 비공개 저장소, SSH 주소, 내부망 주소와 인증정보를 포함한 URL은 지원하지 않는다. 모든 서버의 리디렉션이나 네트워크 정책을 보장하지 않는다.
- 최대 16개 파일과 90,000자까지 선택해 읽는다. 파일 선택과 비밀정보 제외 기준은 GitHub 경로와 공유한다. 전체 소스 감사가 아니다.
- GitHub, GitLab, Bitbucket, Codeberg는 파일 근거 링크를 제공한다. 알 수 없는 호스팅은 저장소 원본 링크와 파일 경로, 줄 번호를 표시한다.

## 확인 범위

2026-09-21에 GitLab의 공개 Node.js 예제와 Codeberg의 공개 문서 저장소를 실제로 수집했다. Bitbucket과 자체 호스팅은 URL 처리 단위 테스트를 통과했으며 실서비스 연결은 별도로 검증하지 않았다. 수집 실패는 AI 분석 전에 처리하므로 AI 분석 한도를 차감하지 않는다.

## 소스 선택과 분량 배분

에이전트 작업 지침, 생성 산출물과 Storybook 폴더는 수집 대상에서 제외한다. 일반 문서, 배포 설정과 UI 표시 코드보다 AI 처리, 결제 실행, 권한, 저장과 정책 구현을 우선한다. 모노레포에서는 한 패키지에 선택이 편중되지 않도록 이미 선택된 파일 수를 반영한다.

GitHub 기본 브랜치 분석은 우선 12개 파일을 읽은 뒤, 상대 경로 및 `@/`로 연결된 구현 파일을 최대 4개 더 선택한다. 이는 제한된 import 해석이며 모든 언어·별칭의 호출 관계를 해석하지는 않는다. GitHub PR은 변경 파일 범위를 유지한다. 다른 Git 호스팅의 Sandbox 수집은 파일 우선순위와 패키지 분산 선택을 사용하며 추가 import 추적은 하지 않는다.

90,000자 문맥 예산을 파일별로 나눠 긴 경로나 앞쪽 파일 때문에 뒤쪽 모듈이 통째로 빠지지 않게 한다. 큰 파일은 시작·끝·중간 구간을 나눠 발췌하며 생략된 구간은 구현 근거로 취급하지 않는다.
