# 프로젝트 AI 활용 학습

AI 워크숍 홈과 `/learn/ai` 상단에서 공개 소스 저장소 또는 GitHub PR을 연결한다. `/learn/ai/project`에서는 기존 저장소 분석을 선택할 수도 있다.

## 학습 범위

- 수집한 실행 코드에 AI 호출 근거가 있는 주제와 새로운 적용 아이디어를 분리한다. README나 의존성 목록에 이름이 있다는 이유만으로 사용 중이라고 판단하지 않도록 모델에 지시한다.
- 최대 6개 주제를 생성한다. 각 주제에는 프로젝트 목적, 코드 인용, 설명, 관련 기본 수업, 작은 실험의 순서와 기대 결과, 대안과 비용 고려, 확인 기준, 선택형 질문이 있다.
- 모델은 GPT-5.6 Sol 이상을 사용하는 기존 프로젝트 분석 설정을 따른다. 저장소 내용은 지시가 아닌 데이터로 취급한다.
- 파일과 줄 번호는 서버에서 실제 수집 코드로 대조하고 본문을 연결한다. 연결할 수업 ID와 선택지 범위도 검증한다. 기술 사용 여부에 대한 의미 판단은 AI 추론이며 런타임 검증이 아니다.
- 기존 분석의 특정 커밋과 코드 일부만 이용한다. 최신 커밋 전체, 도구 설치, 실제 실행과 적용 완료를 확인하는 기능은 아니다. 코드에 AI가 없거나 추가 도입이 적절하지 않으면 해당 주제를 비워둘 수 있다.

## 이용 흐름과 저장

새 저장소 분석 후 학습 생성으로 진행한다. 기존 분석이 있으면 바로 학습을 만들 수 있다. 새 분석 1회와 학습 생성 1회가 프로젝트 분석 한도를 공유한다. 이미 생성된 학습을 조회하거나 답변을 저장할 때는 AI를 다시 호출하지 않는다.

코드 근거 → 관련 개념 수업 → 내 프로젝트 실험 계획 → 확인 문제와 적용 기록 순서다. 관련 수업에서 원래 프로젝트의 주제로 돌아오는 링크를 제공한다. 기록은 저장 버튼으로 서버에 보관하며 수정할 수 있다. 다른 창에서 기록을 바꾸면 리비전 충돌을 알리고 서버 기록을 불러올 수 있다. 기본 수업의 진도는 기존처럼 브라우저에 저장한다.

게스트 쿠키 또는 로그인 계정의 소유 범위를 따른다. 생성 중 화면을 떠나더라도 서버에서 완료한 결과를 다시 조회할 수 있다. 동일 분석의 중복 생성은 작업 잠금으로 막으며 실패한 학습 생성의 개인 및 게스트 접속망 분석 횟수는 환급한다. 공용 호출 한도는 유지한다.

## API와 백업

`/api/project-check/[id]/workshop`의 GET은 저장 결과 또는 null, POST는 생성 또는 기존 결과 재사용, PATCH는 선택 답변과 메모의 리비전 검사를 수행한다. 원본 프로젝트에 대한 소유권을 확인한다.

완료된 결과는 `project-workshop:<분석 ID>` 작업에 저장한다. 원본 분석을 삭제하면 함께 삭제되며, 분석이 삭제된 상태에서 생성이 완료되어도 기록을 되살리지 않는다. 워크스페이스 백업과 SQLite→PostgreSQL 이관에 포함된다.

## 검증

`src/lib/server/project-workshop.test.ts`는 소유권, 중복 생성, 인용과 수업 연결, 답변 저장 충돌, 백업 복원, 실패 횟수 환급, 삭제 중 완료 방지를 검사한다. 공개 FinGuard 코드 발췌로 실제 모델 생성도 확인했다. 학습 효과나 실제 도입 성능을 측정한 것은 아니다.

## 생성 결과의 근거와 정답 처리

학습 생성 입력은 서버가 선택한 코드 구간과 `CFREF_1` 같은 근거 ID로 구성한다. AI는 해당 요청에서 허용된 ID만 선택하며 서버가 원본 파일의 연속 코드 구간으로 변환하고 끝 줄까지 표시한다. 실제 호출·조건이 있는 구간을 인용하도록 요청하며, README 언급이나 import만으로 기존 적용 기술이라고 분류하지 않는다. 잘못된 경로나 임의의 줄 번호를 보정해서 통과시키지 않는다.

AI는 정답 문장과 오답 문장을 분리해 반환한다. 서버가 선택지 순서를 정한 뒤 정답 문장의 위치를 계산하므로 0부터 세는 인덱스와 1번부터 세는 선택지 번호가 혼동되지 않는다. 저장·응답 형식은 기존 `choices`와 `answer`를 유지한다. 이 처리는 번호 불일치를 막으며, 정답 문장 자체의 사실성을 보장하는 것은 아니므로 실제 생성 결과의 내용 검토가 별도로 필요하다.

## 단계별 생성과 최신 코드

화면은 POST에 `{ stepwise: true }`를 보내 기존 AI 활용과 새 적용 아이디어를 두 요청으로 생성합니다. 첫 요청은 `status: pending`과 실제 완료 단계 수를, 마지막 요청은 `status: done`과 `result`를 반환합니다. 완료된 단계는 저장해 재시도 시 재사용합니다. 개인 분석 횟수는 마지막 단계에 한 번 차감하며, 그 단계가 저장되기 전에 실패하면 복원합니다. 모든 AI 요청에는 공용 호출 한도가 적용됩니다. 중간 결과는 개인 백업에서 제외하고 완료된 학습과 답변을 포함합니다.

학습 아래 **최신 코드로 새로 점검**은 별도 분석을 만들고 기존 학습과 답변을 보존합니다. 새 분석과 학습 생성에는 각각 1회가 필요합니다. 근거 ID는 원본 코드에 등장하는 값과 겹치지 않게 발급하므로 실제 오류 코드 `E1` 등을 본문 정리 과정에서 변경하지 않습니다.
