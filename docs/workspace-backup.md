# 학습 기록 백업과 복원

2026-09-19. 환경 설정의 **내 학습 기록 내보내기**는 v3 JSON을 만든다. 기존 v2 코딩 백업도 계속 가져올 수 있다. 백업 파일은 사용자가 수정할 수 있는 개인 기록이며 AI 판정이나 학습 성과의 진위를 인증하는 자료가 아니다.

## 포함 범위

- 본인이 진도나 풀이 기록을 남긴 문제, 본인이 생성한 문제, 이전 백업에서 가져온 문제. 전체 공개 문제 은행은 포함하지 않는다.
- 저장된 코드와 북마크, 힌트·정답 확인 상태, 제출 이력과 기존 보관 자료.
- 서버에 저장된 입문 실습 기록. 복원 시 미션과 기록의 형식·완료 조건을 검증한다.
- 완료된 프로젝트 분석, 수집한 공개 페이지 텍스트와 주소, 화면 이미지, 설명, 제출한 답변과 평가. 보완 회차의 직전 평가와 직접 작성한 확인 기록도 포함한다. 화면 이미지가 포함되면 4 MB 백업 한도에 더 빨리 도달할 수 있다.
- 프로젝트 학습의 최초 답변, 자신감과 도움 사용 기록, 고정된 문항·정답·해설 스냅샷. 복원 시 문항 해시와 점수의 일관성을 검증한다.

보안 점검의 탭 임시 주소·결과·메모, 맞춤 타입 선택, 브라우저에만 남은 미저장 코드·미제출 답변, 실행 중인 AI 요청, 로그인 세션·인증 정보, 사용량 제한과 호출 로그는 포함하지 않는다. 파일에는 비공개 답변과 원문이 있으므로 다운로드 범위를 설정 화면과 개인정보 안내에도 표시한다.

## 일관성과 복원 정책

SQLite는 트랜잭션, PostgreSQL은 읽기 전용 repeatable-read 트랜잭션에서 백업을 읽는다. 가져오기 전에 새 학습 기록의 문항·참조·점수 관계를 검증하며, 실제 삽입은 코딩 기록부터 프로젝트 평가까지 하나의 트랜잭션으로 수행한다. 마지막 평가 저장에서 실패를 주입해 전체 롤백을 확인했다.

기존 코딩 진도, 입문 실습과 프로젝트는 덮어쓰지 않는다. 프로젝트는 분석과 평가·학습을 한 묶음으로 취급하므로 기존 분석만 있는 경우도 부분 병합하지 않는다. 반복 가져오기에서 동일 제출·프로젝트를 중복 생성하지 않는다. 다른 계정으로 가져온 프로젝트는 대상 계정과 원본 ID에서 파생한 새 UUID로 연결하며, 원본 계정의 직접 링크는 새 계정의 기록을 노출하지 않는다. 새 입문 실습과 코드는 대상 저장소의 리비전을 발급한다.

새로 가져온 문제의 계정 연결을 `restored_problems`에 보관한다. 진도 없이 보관한 문제도 재내보내기와 SQLite→PostgreSQL 이관에서 유지한다. 공개 문제의 기존 내용은 수정하지 않는다. 가져온 파일의 서술·점수가 실제 AI 생성 결과라는 진위는 보증하지 않는다.

## 공통 한도

한 파일은 UTF-8 **4,000,000바이트 (4 MB)**, 문제 2,500개, 풀이 10,000개, 입문 실습 500개, 프로젝트 500개까지다. 내보내기와 브라우저 다운로드는 같은 압축되지 않은 compact JSON 직렬화를 사용한다. 개수나 바이트 한도를 넘으면 413으로 거절하며 일부 기록만 내보내지 않는다. 대용량 분할 백업은 아직 지원하지 않는다.

가져오기는 계정당 24시간 5회, 접속망당 10회, 서비스 전체 20회의 제한을 유지한다. 서비스 전체 새 문제 한도는 파일 스키마와 같은 2,500개, 풀이 한도는 10,000개다. 다른 요청이 이미 사용한 일일 한도가 있으면 유효한 백업도 일시적으로 429가 될 수 있으며, 기록 삽입 전에 거절한다. 이전의 새 문제 100개 제한 때문에 정상 백업을 가져올 수 없던 경우를 수정했다. Vercel Functions의 요청·응답 4.5 MB 제한 안에서 오류 메시지까지 전달할 수 있도록 앱 한도를 4 MB로 둔다. 이전 로컬 버전에서 만든 4 MB 초과 파일은 이 웹 가져오기로 복원할 수 없다. 대용량 파일은 별도 이관 도구가 필요하다. 가져오기 전 기존 문제 확인은 ID 500개씩 묶어서 조회하며 최대 5회다.

## 검증

관련 SQLite·HTTP·이관 단위 검사, 실제 격리 PostgreSQL의 공유 저장 계약, 세 브라우저의 다운로드→계정 전환→가져오기→중복 가져오기→프로젝트 재조회 흐름을 검사한다. 자세한 실행 결과는 [검증 기록](VERIFICATION.md)에 남긴다.

`node --import tsx scripts/verify-project-recovery-live.ts`는 호출 계획만 출력한다. `--live`는 합성 프로젝트 페이지와 답변으로 실제 분석·평가 2회를 수행한다. 페이지 수집은 고정 합성 스냅샷을 사용하고 모델 응답은 대체하지 않는다. 두 독립 SQLite DB에서 저장·복원, 최초 답변과 문항 기준, 계정 격리와 추가 유료 호출 없는 재시도를 확인한다. 호출별 모델·비용 추정·지연과 입력·소스 해시를 보고서에 남기고 중단 시 재시도하지 않는다.

이 검사는 제품 신뢰성에 관한 것이며 전문가와의 채점 일치도, 사용자 학습 효과나 SOTA 순위를 입증하지 않는다.
