# 코드 실행 결과의 무결성

## 발견한 오판

2026-09-20에 기존 QuickJS 실행기를 실제로 호출해 네 가지 오판을 재현했다. 기존 구현은 제출 코드와 같은 전역 환경에서 `JSON.stringify(await result)`를 실행했다. 제출 코드가 직렬화 함수를 바꾸거나 반환 객체에 `toJSON`을 넣으면 실제 값 대신 다른 표현으로 비교할 수 있었다. `NaN`과 빈 배열 자리도 JSON 직렬화 과정에서 `null`로 바뀌었다.

| 입력 또는 변경                                     | 이전 비교 값     | 문제                                       |
| -------------------------------------------------- | ---------------- | ------------------------------------------ |
| `JSON.stringify = () => 'true'`, 실제 결과 `false` | `true`           | 실제 실패 값을 통과 값으로 바꿈            |
| `{valid:false, toJSON(){return {valid:true}}}`     | `{"valid":true}` | 반환 객체와 다른 값을 비교                 |
| `NaN`                                              | `null`           | 서로 다른 값을 동일하게 비교               |
| `Array(1)`                                         | `[null]`         | 비어 있는 배열 자리를 명시적인 null로 취급 |

JSON의 변환 규칙 자체는 [ECMAScript 명세](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.stringify)에 정의된 동작이다. 문제는 이 표현을 손실 없이 관찰한 실행 결과로 취급한 코드핏의 비교 방식에 있었다. QuickJS의 호스트 격리와 별개의 문제이며 브라우저나 서버 탈출을 발견한 것은 아니다.

## 현재 실행 계약

`src/lib/handoff/sandbox-bootstrap.ts`를 제출 코드보다 먼저 실행한다. QuickJS에 기본으로 있는 내장 객체, 함수, 프로토타입과 전역 이름을 보호한다. 전역 객체 자체는 동결하지 않아 학습자가 자신의 함수와 변수를 선언할 수 있다. 내장 함수를 바꾸는 대입은 비엄격 코드에서는 무시될 수 있고, 재정의나 엄격 코드에서는 오류가 발생할 수 있다. 일반 브라우저의 모든 JavaScript 동작을 지원하는 환경은 아니다.

부트스트랩이 반환한 직렬화 함수는 호스트가 가진 핸들로만 보관한다. 학습자 전역 변수로 공개하지 않는다. 비동기 테스트가 완료되면 호스트가 이 함수를 호출한다. 테스트 표현식의 기본 메서드도 보호하므로 `Array.prototype.every` 등을 바꿔 조건 검사를 건너뛰지 못하게 한다.

비교 대상은 다음과 같다.

- 문자열, 유한한 숫자, 불리언과 null.
- 일반 객체 또는 null 프로토타입 객체의 열거 가능한 자체 데이터 속성.
- 빈 자리가 없고 추가 열거 속성이 없는 배열. 숫자 0과 -0은 기존 JSON 비교처럼 동일하게 취급한다.
- 위 값으로 완료되는 Promise. 각 항목을 재귀적으로 확인하고 원문 문자열은 JSON 이스케이프한다.

`NaN`, 무한대, undefined, 함수, Symbol, BigInt, Date, Map, 순환 참조, 배열의 빈 자리와 지원하지 않는 속성은 오류로 안내한다. 결과를 직렬화하기 위해 getter나 `toJSON`을 호출하지 않는다. 학습자 코드나 테스트 표현식 자체에서 속성을 읽는 동작까지 금지하는 것은 아니다. 예를 들어 Date가 필요하면 함수가 비교할 문자열이나 숫자를 직접 반환하면 된다.

출력은 1,600자, 방문 항목은 1,000개, 중첩은 40단계로 제한한다. 기존의 테스트별 0.6초, 메모리 16MB, 스택 256KB와 브라우저 Worker의 전체 12초 중단 제한을 유지한다. 무한 반복, 끝나지 않는 Promise와 실행 예산을 소모하는 Proxy도 오류로 종료한다. 각 테스트는 새 런타임과 컨텍스트를 사용하고 핸들을 정리한다. DOM, 네트워크, 타이머, 모듈 로더나 호스트 함수를 추가하지 않았다. [QuickJS 라이브러리의 컨텍스트·메모리 계약](https://github.com/justjake/quickjs-emscripten)을 따른다.

## 기존 기록과 사용자 안내

실행 버전은 `2026-09-20.1`이다. 저장된 코드와 실행 기록을 삭제하거나 재채점하지 않는다. 이전 `suiteVersion`의 결과는 화면에서 이전 실행 결과로 표시하며, 사용자가 다시 실행하면 새 계약의 결과를 저장한다. 코드가 바뀐 뒤의 결과를 오래된 코드 결과로 혼동하지 않도록 기존 코드 해시 대조도 유지한다.

코드 실행 영역과 `/quality`에서 지원하는 값과 제한을 설명한다. 오류를 본 사용자는 코드를 수정하고 같은 화면에서 다시 실행할 수 있다.

## 재현과 한계

`node --import tsx scripts/verify-sandbox-integrity.ts`는 Git 커밋 `43eb771e1cf3aa7e40dd6c9e626e7c07364f60b8`의 검토된 실행기와 현재 실행기에 같은 합성 입력 네 개를 넣는다. 두 버전 모두 QuickJS 내부에서 실행하며 사용자 코드를 Node에서 직접 실행하지 않는다. 비교 결과, 코드 해시와 참고 정답 검사는 `reports/sandbox-integrity.json`에 저장한다.

재현 결과 오답 통과는 **4/4 → 0/4**이며, 기본·응용 과제 12개의 참고 정답 체크포인트 **40/40**을 유지했다. 단위 검사는 내장 함수 변조, toJSON, getter, 유한하지 않은 수, 빈 배열 자리, 순환 참조, 출력 제한, 비동기 종료와 오류 후 재실행을 포함한다.

이는 코드핏의 제공된 테스트에서 발견한 문제를 수정한 근거다. 제출자는 테스트를 읽거나 특정 입력의 답을 하드코딩할 수 있고, 브라우저 기록도 수정할 수 있다. 이를 조작 불가능한 성적, 완전한 샌드박스 보안 감사, 모든 입력의 정답 또는 학습 효과의 증거로 표현하지 않는다. 운영 데이터나 유료 AI는 사용하지 않았다. 관련 단위 검사 61건과 Chromium/Firefox/WebKit의 실제 Worker 시나리오 12건을 통과했다. 세부 환경과 범위는 [검증 기록](VERIFICATION.md#코드-실행-결과-무결성--2026-09-20)에 있다.
