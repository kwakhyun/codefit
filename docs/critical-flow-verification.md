# 핵심 흐름 검증

일반 PR과 main 푸시의 CI는 기존 정적 검사와 단위 테스트에 더해 프로덕션 빌드와 `npm run test:e2e:ci`를 실행한다. 전체 Chromium, Firefox, WebKit 검사는 수동 `full_browser_tests` 옵션으로 실행한다.

최소 Chromium 검증은 `e2e/ci-smoke.spec.ts`에 둔다.

1. 프로젝트 점검 진입과 새로고침 후 입력 초안 복원
2. 모의 분석의 이동·새로고침 복구와 중복 생성 요청 방지
3. 로컬 서버의 계정별 프로젝트 격리와 이전 계정 요청 거절
4. 설정 화면에서 백업 다운로드와 다른 계정으로 복원

공급자 응답을 모의 처리하거나 AI 키가 없는 격리 서버를 사용한다. 운영 DB나 실제 유료 AI를 사용하는 시험이 아니다. 전체 브라우저 시험을 대신하거나 실제 생성 콘텐츠의 오답률을 측정하지 않는다.

생성 경로의 회귀는 `project-content-quality.test.ts`와 `project-ai-calls.test.ts`에서 별도로 확인한다. 정답을 숨긴 심사 입력, 의미 검증 실패 후 저장 거절, 한 차례 보정과 근거 없는 항목 제거, 공급자 호출별 한도·계측, 예산 소진 시 후속 호출 중단을 검증한다. 저장소 수집과 백업은 해당 모듈의 테스트 및 양쪽 DB의 공유 계약으로 검증한다.
