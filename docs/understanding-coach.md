# 원본 실행을 근거로 한 AI 질문

이 문서는 `/handoff?source=sample`의 샘플 코드 훈련을 설명한다. 실제 GitHub 코드로 만드는 훈련은 [내 프로젝트로 연습](project-practice.md)을 참고한다.

샘플 이해 훈련은 먼저 예측을 남기고 원본을 브라우저의 QuickJS에서 실행한다. 그다음 수정 중인 코드와 예측 이유를 함께 보내 질문을 받는다. 두 코드가 달라질 수 있으므로 AI가 수정 코드의 동작을 원본 실행의 이유로 설명하면 학습 근거가 어긋난다.

## 2026-09-20 변경

- 원본 코드, 실행식과 식별자, 실행기 버전을 SHA-256으로 묶어 관찰 기록에 보존한다. 식별값이 없거나 현재 원본과 다르면 이전 결과를 그대로 보여 주되, AI 요청 전에 원본을 다시 실행하게 한다. 첫 예측은 유지한다.
- 서버가 현재 교육용 원본의 고정 실행 결과와 보고된 값을 비교한다. 기본·응용 과제 12개의 기준값은 실제 QuickJS 실행으로 검사한다. 원본이 배포된 교육 자료와 다르면 기준값을 적용하지 않는다. 식별값이나 결과가 맞지 않으면 AI 작업 생성과 이용 한도 소비 전에 거절한다. 제출 코드는 서버에서 실행하지 않는다.
- AI 응답 대기 중 예측, 실행 결과나 출처가 바뀌면 이전 질문을 새 기록에 붙이지 않는다. 그동안 작성한 코드와 메모는 보존한다. 보관된 질문의 근거가 현재와 다르면 화면에서 구분한다.
- 모델에 함수의 입력 계약을 전달하고 원본과 수정 코드의 역할, 정상 동작과 새 요구사항, 접근 가능한 반환값, 실패 후 재시도를 위한 예외 처리를 설명한다. 올바른 예측 이유에 임의의 오해를 덧붙이지 않도록 했다.
- 모델 기본값은 기존 Luna를 유지한다. 필요한 환경은 `OPENAI_COACH_MODEL`로 코칭만 변경할 수 있으며, 응답 이전 실패에서도 선택한 모델을 사용 기록에 남긴다.

출처 식별값은 정상적으로 저장된 오래된 기록을 구분하는 장치다. 클라이언트가 실제로 실행했다는 증명은 아니다. 서버 결과 비교 역시 정해진 한 사례의 일치만 확인하며 사용자의 이해도, 다른 입력의 정답 또는 조작 불가능한 시험 성적을 보장하지 않는다. 기준값은 공개 lab 응답에 정답 필드로 포함하지 않는다.

## 실제 호출에서 확인한 문제

합성 사례 8개를 같은 순서로 총 다섯 번 호출했다. 사례는 원본/수정 참조, 같은 검색어의 응답 순서, 정상 설정 변환, 정상 합계 보존, 실패 후 재시도, 빈 페이지, 지시 삽입, 원본과 맞지 않는 보고 결과다. 각 입력의 원본은 평가 전에 QuickJS로 실행했다. 마지막 사례만 의도적으로 다른 보고 값을 넣었다.

변경 전에는 문자열만 받는 검색어에 객체를 제안하고, 문자열 또는 생략만 허용하는 환경 설정에 불리언을 제안했다. 원본의 `seen` 동작을 수정 코드의 `jobs`로 설명하거나 외부에서 읽을 수 없는 지역 변수를 확인하도록 요청하기도 했다. 원본과 맞지 않는 결과를 수정 코드로 설명하는 응답도 있었다.

첫 수정 뒤 이런 문제가 줄었지만, 추가 지침을 넣은 중간 버전은 학습자의 틀린 예측을 원본/실행 버전 문제로 오해했다. 최종 `2026-09-20.coach.2.2`의 Luna 응답에서는 두 해당 사례의 잘못된 출처 경고가 사라졌다. 다만 불일치 결과에 대한 질문과 다음 행동의 설명이 매끄럽게 이어지지 않았다. 이 입력은 최종 제품 API에서 모델 호출 전에 거절하도록 했다.

동일 최종 프롬프트의 Terra는 이 작은 표본에서 중앙 응답 시간이 더 짧았다(Luna 5.13초, Terra 2.46초). 8회 추정 비용은 각각 $0.0058766과 $0.029198이었다. Terra도 원본에 없는 `cancelled` 값이나 `undefined` 반환을 JSON으로 안전하게 관찰하는 방법을 생략했다. 일관된 품질 우위를 확인하지 못했으므로 기본 모델을 바꾸지 않았다. 모델 전반의 속도나 정확도 비교로 일반화하지 않는다.

다섯 실행의 총 **40회, 추정 토큰 비용 $0.0482736**이다. 실제 청구액이 아니다. 중간 실패와 전체 원문, 입력, 사용량, 프롬프트 버전과 해시는 [집계 보고서](../reports/understanding-coach-reliability.json)에서 연결한다. 원문 파일은 수정하지 않았으며 사례별 검토를 별도 보고서에 남겼다.

## 검증과 남은 범위

검토는 개발 에이전트가 수행한 정성 진단이다. 8개 사례를 반복 사용했고, 초기 실행 이후 입력 계약도 추가했으므로 독립 평가, 동일 입력의 통계적 비교나 정확도 수치로 표현하지 않는다. 직접 모델 호출은 HTTP 사전 검사를 통과시키지 않으며, 사전 검사는 별도의 API/브라우저 테스트로 검증한다.

위 `coach.2.2` 진단 당시 다음 실험은 설명문이었다. 이후 `coach.3`에서 실행 가능한 표현식과 사용자 편집·비교 실행을 추가했다. [직접 실험 기능과 추가 검증](learning-experiments.md)에 연결 과정을 기록했다. 모든 미래 제안의 의미나 타당성을 보장하지는 않는다. 독립된 새로운 사례, 외부 평가자, 경쟁 제품 비교와 실제 학습 전이는 별도 근거가 필요하다.

재현 명령:

```sh
npx vitest run src/lib/server/ai-coach.test.ts src/lib/server/understanding-coach-route.test.ts src/lib/handoff/training.test.ts
npx playwright test e2e/understanding.spec.ts --grep 'prediction.*real execution|mobile prediction|coaching API|coaching failure|legacy observation|late coaching'
node --import tsx scripts/evaluate-understanding-coach.ts
node --env-file=.env.local --import tsx scripts/evaluate-understanding-coach.ts --live --model gpt-5.6-luna
```

마지막 명령만 실제 유료 호출 8회를 수행한다. API 키와 운영 사용자 데이터는 보고서에 저장하지 않는다. 전체 테스트나 운영 배포는 이번 검증에 포함하지 않는다.

## 후속 개선

설명의 명시적 주장을 인용하고 해당 오류를 구별하는 실행식을 제안하는 작업은 [학습자의 설명을 검증하는 코칭](coach-targeting.md)에 기록했다. 위 기록은 이전 프롬프트의 검증 이력이다.
