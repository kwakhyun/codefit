# 저장소 학습 콘텐츠 검증

공개 저장소의 프로젝트 점검, 코드 이해 훈련, 서비스 동작 실습은 수집한 커밋의 정적 코드에 근거한다. 실제 서비스 실행이나 저장소 전체의 동작을 인증하지 않는다.

## 수집과 생성

- 문서, 검증 스크립트, 로딩 화면과 장식 컴포넌트보다 실행 코드와 도메인 처리를 우선한다. 후보가 적은 프로젝트에서는 화면 구현도 수집한다.
- 최초 8개 파일에서 확인한 import를 두 차례 따라가며 최대 16개 파일을 읽는다. PR은 변경된 줄 주변으로 범위를 제한한다.
- 파일별 발췌와 전체 컨텍스트 크기는 제한한다. 짧은 함수의 앞선 반환 조건과 뒤쪽 분기가 함께 남도록 수집한다. 호출 관계의 완전성을 보장하지 않는다.
- 서버가 발급한 근거 ID를 실제 코드로 복원하고, 인용과 선택지 형식을 검증한다. 선택지는 공백과 유니코드 표기를 정규화하여 중복을 검사한다.

## 저장 전 품질 검사

생성 요청과 별도의 모델 요청으로 새 콘텐츠를 검토한다. 실습 정답 인덱스를 제공하지 않고 검토 모델이 선택지를 다시 판정하게 한다. 정확히 한 선택지를 지지하며 생성된 정답과 일치해야 통과한다.

검토 대상은 잘못된 단정, 결정적 근거 누락, 복수 정답, 답안 공개 전 문구의 정답 노출, 반복 시나리오, 사용자 행동과 관찰 결과가 없는 서비스 실습이다. 해설은 답안 공개 후 제공되므로 정답 노출 검사와 구분한다. 프로젝트 점검의 열린 설계 질문과 향후 검증 계획은 구현 사실을 단정하는 문장과 구분한다.

주변 코드는 앞선 반환 조건 등 모순을 찾는 데만 쓴다. 학습자에게 보여 주지 않은 주변 코드로 정답의 근거 부족을 보충하지 않는다. 모든 문항의 검토 ID가 정확히 한 번 반환되어야 한다.

품질 문제를 찾으면 지적 사항과 이전 초안으로 한 번 수정하고 다시 검사한다. 지적되지 않은 문항은 서버에서 원문 그대로 유지해, 수정 과정에서 새로운 문제가 생기는 범위를 줄인다. 요청 취소와 최대 105초의 생성 제한은 수정 요청에도 이어진다. 재검사 실패, 시간 초과, 잘못된 응답이 발생하면 미검증 초안을 반환하거나 저장하지 않는다. 이미 완료된 학습 단계는 기존 저장 절차에 따라 유지한다. 추가 검토와 수정은 API 비용과 응답 시간을 늘린다.

모델 검토도 오판할 수 있으므로 통과율은 정답률이나 모든 저장소에 대한 보증이 아니다. 원문과 생성 결과의 표본 검토를 함께 수행해야 한다. 기존에 저장된 학습 기록은 자동으로 재생성하지 않는다.

## 재현 가능한 유료 검증

아래 명령은 DB에 쓰지 않으며, 보고서는 Git에서 제외된 `artifacts/` 아래에만 저장한다. `--live`가 없으면 API를 호출하지 않는다.

```sh
node --env-file=.env.local --import tsx scripts/evaluate-project-content.ts \
  --live --url https://github.com/OWNER/REPO \
  --out artifacts/project-content/result.json
```

움직이는 기본 브랜치 대신 저장된 보고서의 소스 스냅샷으로 재생성할 수 있다.

```sh
node --env-file=.env.local --import tsx scripts/evaluate-project-content.ts \
  --live --snapshot artifacts/project-content/result.json \
  --out artifacts/project-content/recheck.json
```

각 단계의 시간, 생성 결과, 분석 호출 정보와 최종 품질 실패 사유를 남긴다. 단계가 실패하면 종료 코드 1을 반환한다. 개인 프로젝트의 평가 내용과 보고서는 공개 문서나 테스트 데이터에 복사하지 않는다.
