# 화면 테마

`src/styles/tokens.css`가 공통 색상 역할과 라이트 팔레트를 정의한다. 기존 화면의 다크 색상은 각 선언의 `light-dark(라이트 역할, 다크 값)` 쌍으로 보존한다. 배경, 본문, 보조 글자, 테두리, 강조색과 강조 배경을 구분하며, 새 UI는 먼저 `--bg`, `--surface`, `--text`, `--muted`, `--action`, `--success`, `--warning`, `--danger` 등의 공통 토큰을 사용한다.

- 기본값은 시스템 설정이다. 명시적으로 선택한 라이트/다크 설정이 운영체제 설정보다 우선한다.
- `ThemeProvider`는 시스템 변경과 다른 탭의 저장소 변경을 구독한다. 선택은 이 브라우저의 `codefit-theme-v1`에 저장하며 계정 설정과는 별개다.
- 루트 레이아웃의 초기 스크립트는 본문 표시 전에 저장된 설정을 적용한다. 저장소가 차단되면 시스템 설정으로 시작하며 현재 페이지에서의 수동 전환은 계속 동작한다.
- JavaScript 없이도 `color-scheme: light dark`와 CSS 색상 쌍이 운영체제 설정을 따른다. 수동 선택 및 저장은 JavaScript가 필요하다.
- 공통 헤더, 사이드바, 환경 설정에서 같은 선택 상태를 사용한다. 모바일 사이드바의 키보드 포커스 순서에 네이티브 선택창도 포함한다.
- Monaco는 다크 모드에서 기존 `recode-terminal`, 라이트 모드에서 `vs` 테마를 사용한다. 테마 변경은 편집기 모델을 교체하지 않는다.
- 이미지 자체의 색상, 브랜드 이미지, 모달 배경을 가리는 검은 반투명 레이어와 그림자는 의도적으로 고정한다. 라이트 모드의 삽화는 합성 효과와 가장자리 페이드를 제거해 밝은 배경에서도 보이도록 한다. 시뮬레이션 내부의 폼과 콘텐츠는 상위 테마를 상속한다.

## 검증

`e2e/theme.spec.ts`는 주요 경로를 라이트/다크와 1440px/390px 너비에서 검사한다. axe의 글자 대비 검사, 가로 넘침, 환경 설정 및 모바일 메뉴, 학습 선택/결과, 저장소 오류, 운영체제 변경, 탭 동기화, JavaScript 없는 초기 렌더링과 편집기 모델 유지를 다룬다. 이 검사는 해당 화면 상태의 대비를 검증하며 외부 AI 호출로 생성되는 모든 내용이나 모든 조작 조합의 완전성을 보증하지 않는다.

실행 중인 로컬 서버를 사용할 때:

```sh
CODEFIT_E2E_EXTERNAL_SERVER=1 CODEFIT_E2E_BASE_URL=http://127.0.0.1:3012 npx playwright test e2e/theme.spec.ts --project=chromium --reporter=list --output=artifacts/theme-verification
```

브라우저는 CSS `light-dark()` 지원이 필요하다. 새 색상이나 선택/호버 상태를 추가할 때 두 테마에서 전경과 배경을 함께 확인하고, 작은 보조 글자에 불필요한 투명도를 적용하지 않는다.

2026-09-21 로컬 검증: 주요 경로 18개 × 테마 2개 × 너비 2개에서 글자 대비와 가로 넘침 검사를 통과했다. Chromium의 테마 관련 47개 시나리오와 Firefox/WebKit의 설정·편집기·메뉴·초기 표시 관련 14개 시나리오를 수정 영향별로 나누어 검증했다. 변경된 TypeScript 진입점의 타입 검사, ESLint 및 Prettier 검사도 통과했다.
