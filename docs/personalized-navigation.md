# 사용자 타입에 따른 탐색

맞춤 타입은 학습 기록이나 권한을 바꾸지 않는 브라우저 표시 설정이다. 모든 타입에서 분야별 문제, 북마크와 학습 기록에 접근할 수 있다. 기존 홈 고정 가이드의 위치와 동작은 유지한다.

| 타입           | 이전 개발 경험 / 목적 | 주요 메뉴 순서                            | 홈 우선 콘텐츠                                                       | 이어하기                                             |
| -------------- | --------------------- | ----------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 원리 입문      | beginner / learn      | 서비스 원리 → 코드 이해 → 프로젝트 → 보안 | 미완료 원리 실습 또는 다음 기초 미션, 저장과 권한 예제               | 원리 학습을 먼저, 작성 중 코드는 별도 영역           |
| 코드 훈련      | developer / learn     | 코드 이해 → 프로젝트 → 보안 → 서비스 원리 | 작성 중인 코드 또는 장바구니 인수인계, 검색 가능한 문제 목록         | 작성 중 코드를 먼저, 원리 학습은 별도 영역           |
| 내 서비스 이해 | beginner / project    | 프로젝트 → 서비스 원리 → 보안 → 코드 이해 | 프로젝트 질문/피드백 예시 또는 최근 점검, 접근 권한과 중복 예약 연습 | 로그인한 본인의 최근 프로젝트, 기존 코드와 원리 학습 |
| 배포 전 점검   | developer / project   | 보안 → 프로젝트 → 코드 이해 → 서비스 원리 | 공개 보안 설정과 수동 확인 기록, 설계 설명/보완 답변                 | 로그인한 본인의 최근 프로젝트, 기존 코드와 원리 학습 |

## 선택과 보관

- 홈의 이미지 카드는 아직 타입을 고르지 않은 경우에만 표시한다. 첫 선택 후 카드는 사라지고 제목으로 포커스를 옮기며, 타입별 콘텐츠가 우선 표시된다. 이후 변경은 헤더에서 한다.
- 홈의 이미지 카드와 공통 헤더의 ‘맞춤 타입 변경’ 대화상자는 같은 선택 컴포넌트를 사용한다. 전체 카드가 라디오 선택 영역이며 키보드 화살표로 이동할 수 있다. 선택은 즉시 반영하고, 대화상자를 닫으면 진입 버튼으로 포커스를 돌려준다.
- `codefit-learning-preference-v2`에 `{ version: 2, type }` 형식으로 저장한다. 기존 v1의 네 조합을 위 표에 따라 자동으로 옮긴다. 같은 브라우저의 탭 사이에는 storage 이벤트로 갱신한다.
- 로그인과 로그아웃으로 설정이 달라지지 않는다. 공용 브라우저에서는 다른 사용자에게도 같은 화면 구성이 적용된다는 사실을 선택 화면과 개인정보 안내에 명시한다. 계정별 동기화 기능은 아니다.
- 저장소가 막혀 있으면 현재 화면의 메모리에서만 적용하고 재방문 때 유지되지 않을 수 있음을 표시한다. 언제든 다른 카드로 되돌릴 수 있다.
- 프로젝트 이어하기는 현재 연습실 범위를 확인한 응답만 표시한다. 화면 변경을 위해 AI를 호출하거나 이용 횟수를 차감하지 않는다.

## 문제 탐색

사이드바의 홈 내부 앵커 링크를 없애고, 전체 문제는 `/?view=browse`로 이동한다. 이 상태를 필터, 페이지 이동과 문제 풀이의 돌아가기 주소에 보존한다. 분야별 문제는 접기 없는 목록으로 항상 제공한다. 메뉴가 길면 사이드바 탐색 영역만 스크롤되고 하단 환경 설정은 별도로 남는다.

## 이미지 자산

새 외부 이미지나 외부 이미지 서비스를 추가하지 않았다. 기존 코드핏용 내장 이미지 생성 도구로 제작한 WebP 자산을 재사용한다.

- 원리 입문: `public/images/features/app-foundations.webp` — 화면, 서버와 저장소를 연결한 장면.
- 코드 훈련: `public/images/features/read-code.webp` — 코드와 실행 결과를 비교하는 장면.
- 내 서비스 이해: `public/images/features/debug-lab.webp` — 서비스의 중복 데이터를 살펴보는 장면.
- 배포 전 점검: `public/images/scenarios/container.webp`의 네 번째 장면 — 서버, 배포 흐름과 확인 목록.

제작 경위는 `docs/design/feature-banner-prompts.json`과 `docs/design/scenario-visuals.md`에 있다. 세로 가로 비율을 고정하고 이미지 자체의 글자에 선택 의미를 의존하지 않는다. 이름과 설명은 HTML로 제공하므로 이미지 로드 실패 시에도 선택 가능하다.

## 검증 범위

`src/lib/learning-preference.test.ts`, `src/lib/library-state.test.ts`에서 이전 선택값의 대응과 탐색 URL 보존을 확인한다. `e2e/learner-types.spec.ts`는 타입별 구성, 데스크톱/모바일 카드, 키보드와 포커스, 이미지/저장소 실패, 코드 보존 및 로그인 전후 설정을 검증한다. `e2e/anchor-navigation.spec.ts`는 전체 문제 탐색의 새 진입 경로를 검증한다. 계정 검증은 격리된 로컬 테스트 계정과 합성 프로젝트 기록을 사용하며 실제 사용자 내용이나 AI 응답 품질을 평가한 결과가 아니다.
