# 작업 공간에 따른 홈과 탐색

작업 공간은 학습 기록과 권한을 바꾸지 않는 브라우저 표시 설정이다. 세 공간 모두 모든 기능에 접근할 수 있지만 홈 구조와 메뉴 순서가 다르다.

| 작업 공간     | 홈 구조                                                                              | 메뉴 묶음 순서                         |
| ------------- | ------------------------------------------------------------------------------------ | -------------------------------------- |
| 서비스 점검실 | 서비스 점검 진입, 최근 프로젝트, 설계 설명에서 검증까지의 절차, 보안 점검, 원리 보충 | 내 서비스 점검 → AI 활용 → 코드와 원리 |
| AI 워크숍     | 내 프로젝트 AI 학습 진입, 학습 현황과 최근 수업, 목적별 학습 경로, 확장 주제         | AI 활용 → 코드와 원리 → 내 서비스 점검 |
| 코딩 트레이닝 | 작성 중 코드, 10개 분야 선택, 코드 이해 훈련, 검색 가능한 문제 목록                  | 코드와 원리 → AI 활용 → 내 서비스 점검 |

메뉴 묶음은 기능의 성격으로 나눕니다. 내 서비스 점검은 내 프로젝트 점검과 서비스 보안 점검, AI 활용은 AI 실무 배우기와 내 프로젝트 AI 워크숍, 코드와 원리는 AI 코드 이해 훈련, 분야별 코딩 연습, 서비스 원리 배우기입니다. 작업 공간은 어느 묶음이 맨 앞에 오는지만 정합니다. 코딩 트레이닝에서는 코드와 원리 묶음이 분야별 코딩 연습부터 시작하고 그 아래에 10개 분야 바로가기를 둡니다. 묶음 앞에는 홈과 내 프로젝트, 뒤에는 북마크와 내 학습 기록이 항상 같은 자리에 있습니다. 정의는 `src/lib/learning-preference.ts`의 `navigationGroups`입니다.

서비스 점검실과 AI 워크숍은 기존 히어로 안에 공개 저장소 입력창을 통합한다. 서비스 점검실은 점검과 실습, AI 워크숍은 프로젝트 AI 활용 학습으로 연결한다. 코딩 트레이닝은 저장소 입력창 없이 분야별 코딩 문제와 작성 중인 코드부터 보여준다. 공간 선택 전에도 프로젝트 점검 질문 5개와 코드 훈련 3개, 서비스 동작 실습 3개를 함께 준비할 수 있다.

## 선택과 기록

- 첫 방문에는 공개 저장소 입력창 아래에 세 공간의 이미지 카드를 보여준다. 선택 후에는 전용 홈으로 이동하고 헤더의 ‘작업 공간 변경’에서 다시 고른다.
- 라디오 선택은 즉시 반영한다. 첫 선택 후 제목에 초점을 옮기고 대화상자를 닫으면 진입 버튼으로 돌아간다.
- 기존 저장 키 `codefit-learning-preference-v2`를 유지하되 값은 `{ version: 3, type: "service" | "ai" | "code" }`다.
- 같은 선택을 `codefit-workspace` 쿠키(값은 `service`, `ai`, `code` 중 하나, 1년)에도 남긴다. 루트 레이아웃이 이 쿠키를 읽어 서버에서도 같은 메뉴 순서로 그리므로 첫 화면에서 메뉴가 다시 정렬되지 않는다. 브라우저 저장소가 기준이며, 쿠키가 없던 이전 선택은 다음 방문부터 반영된다. 서버는 쿠키 값을 기록하지 않는다.
- 기존 원리 입문은 AI 워크숍, 코드 훈련은 코딩 트레이닝, 내 서비스 이해와 배포 전 점검은 서비스 점검실로 옮긴다. 이전 v1 조합도 같은 기준으로 처리한다.
- 선택은 계정과 관계없이 브라우저에 저장한다. 저장 실패 시 메모리에서만 적용하고 안내한다. 다른 탭의 변경은 storage 이벤트로 반영한다.
- AI 워크숍의 진도는 기존 AI 학습 저장소를 읽고, 최근 변경한 미완료 수업을 이어준다. 서비스 점검실은 현재 범위의 프로젝트 기록을 조회한다. 공간 변경으로 학습 기록이나 작성 코드를 수정하지 않는다.
- 처음 공간을 고르기 전에는 공개 저장소 입력과 공간 선택 아래에 ‘이런 기능도 있어요’ 카드 목록을 둔다. 자동으로 넘어가지 않는 6개 카드(서비스 보안 점검, AI 실무 배우기, AI 코드 이해 훈련, 서비스 원리 배우기, 분야별 코딩 연습, AI 문제 생성)에 메뉴와 같은 이름과 한 줄 설명을 쓴다. 선택 후에는 공간별 홈이 이를 대체한다.
- 공간별 홈에서 샘플로 연결하는 링크(서비스 점검실의 ‘서비스 원리 배우기 →’, 코딩 트레이닝의 ‘AI 코드, 실행 전에 읽어보기’)는 `?source=sample`을 붙인다.

## 이미지

내장 image_gen으로 공간별 이미지를 생성하고 1200×800 WebP로 저장했다. 실제 실행 화면이 아닌 장식용 그림이며 제목과 설명은 HTML로 제공한다. 이미지가 로드되지 않아도 공간을 고를 수 있다.

- `public/images/personas/persona-service.webp`: 파란 서비스 화면, 돋보기, 데이터와 권한 모듈
- `public/images/personas/persona-ai.webp`: 보라색 문서, 워크플로우, 모델과 열린 책
- `public/images/personas/persona-code.webp`: 호박색 코드 화면, 테스트 타일과 키보드

전체 생성 프롬프트는 [제작 기록](design/workspace-visuals.json)에 있다.

## 검증

`src/lib/learning-preference.test.ts`는 기존 선택값 이전, 새 공간 복원, 메뉴 묶음과 우선순위, 전체 기능 유지, 쿠키 값 검증을 확인한다. `e2e/learner-types.spec.ts`는 세 홈의 구분, 이미지, 모바일 넘침, 저장소 실패와 코드 초안 보존을 다룬다. 공간 변경은 유료 AI 호출을 실행하지 않는다.

작업 공간 선택창은 카드를 누르면 즉시 적용하고 닫는다. 이미 선택된 카드를 다시 눌러도 닫히며 별도의 완료 버튼은 없다. 모든 경로의 헤더는 메뉴, 로고, 작업 공간 변경, 테마, 사용 안내를 같은 순서로 둔다. 휴대폰의 코딩 홈과 문제 풀이에서는 AI 문제 생성과 새로고침을 ‘빠른 작업’에서 연다.
