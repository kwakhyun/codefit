조사 시점: 2026-09-18 03:29 KST. 현재 로컬 README와 메인 학습 경로, 공개 서비스 소개, 레지스트리 RDAP, Vercel 도메인 조회 도구 및 가비아 등록 검색 화면을 확인했다. 도메인을 구매하거나 서비스명을 변경하지 않았다.

## 판단

장기적인 공개 서비스 브랜드로는 변경을 권한다. Code + Fit은 반복 훈련이라는 서비스의 공통점을 여전히 잘 표현하고, 짧은 한국어 발음과 기존 로고도 장점이다. 서비스 범위가 늘었다는 이유만으로 폐기할 이름은 아니다.

그러나 현재 핵심은 개발자 손코딩 유지에서 더 넓어졌다. 비개발자의 앱 원리 학습, AI 생성 코드 이해, 오류 재현과 수정 결과 검증을 함께 제공한다. 기존 이름은 이 중 코딩 훈련을 가장 먼저 연상시키며 비개발자 입구와 이해/판단 역량은 부제에 의존한다. 이는 브랜드 해석이며 실제 사용자 인식 조사 결과는 아니다.

결정적인 약점은 같은 이름의 개발자 학습 앱과 AI 기반 학습 안내 프로젝트가 확인됐다는 점이다. 기능 확장은 부제로 설명할 수 있지만, 동명 서비스의 검색과 소개 과정에서 생기는 구분 비용은 부제만으로 해소하기 어렵다. `CODE:FIT`, `CodeFit`, `Codefit AI`처럼 표기만 바꾸는 방안은 충분한 구별 방법으로 보지 않는다.

기존 서비스의 실제 사용자 규모, 유입 검색어와 브랜드 인지도는 조사하지 않았다. 현재 사용자 수가 적다고 가정하지 않는다. 이미 인지도가 높다면 전환 비용을 다시 평가해야 한다. 포트폴리오 자료와 외부 링크의 일관성은 유지의 장점이다. 변경한다면 한동안 `새 이름(구 CODE:FIT)`을 병기하고 기존 서비스 URL을 보존하는 방식이 적절하다.

## 유지와 변경을 비교한 권고

- 유지: 이름이 짧고 반복 훈련이라는 의미가 남아 있다. 로고, README, 로그인 앱 이름과 외부 소개를 바꿀 비용이 없다. `codefit.app`이나 `codefit.kr`도 확보 가능한 선택지다.
- 변경: 학습 분야의 동명 서비스와 구별할 수 있고, 앱 원리부터 AI 코드 검토까지를 새로운 소개 문장으로 묶을 수 있다. 대신 로고, 메타데이터, 공유 이미지, OAuth 표시 이름과 공개 자료를 일관되게 바꿔야 한다.
- 권고: 공개 브랜드를 더 확장하기 전에 새 이름을 정하는 편이 낫다. 가장 큰 근거는 도메인 가격이나 기능 증가가 아니라 동일/인접 분야의 명칭 중복이다. 새 이름 확정 전에는 현행 이름을 유지하며, 이번 검토만으로 운영 설정을 바꾸지 않는다.

새 이름의 기준은 한국어로 말하기 쉬움, 비개발자에게도 열린 인상, 이해하고 검증하는 연습의 의미, 정확한 철자의 주요 도메인 확보, 동일 분야의 낮은 혼동 가능성이다. `AI`라는 접미사와 무료로 남은 도메인만을 기준으로 정하지 않는다.

탐색 후보로는 `앱리허설 / AppRehearsal`을 조회했다. 실서비스를 다루기 전에 예상하고 실험한다는 의미는 적합하고, [apprehearsal.com](https://vercel.com/domains/search?q=apprehearsal.com)은 Vercel에서 1년 USD 11.25로 등록 가능했다. 정확한 영문/한글 검색에서 명확한 동명 서비스는 발견하지 못했지만, 영문 철자가 길고 UI 테스트 도구로 오해할 여지가 있다. 최종 추천명이나 상표 사용 가능 판정은 아니다.

`빌드루틴 / BuildRoutine`도 비교했으나 정확한 .com은 등록 불가였다. buildroutine.app은 USD 9.99/1년, buildroutine.ai는 USD 160/2년으로 조회됐다. ‘만드는 습관’은 표현하지만 코드 이해와 판단이라는 차별성을 충분히 설명하지 않아 이름 변경의 주된 추천안으로 삼지 않았다.

이 검토는 공개 명칭과 도메인 조사다. 상표 등록 가능성, 유사 상표와 지정상품에 대한 전문 검토나 이용자 대상 이름 선호도 조사를 완료했다는 뜻은 아니다.

## 도메인 구매와 시장 경쟁력의 구분 — 후속 검토

2026-09-18 후속 질문에 따라 현재 구현과 대체 서비스의 공개 소개를 대조했다. 코드핏이라는 이름으로 성공할 가능성을 배제하지 않는다. 다만 도메인 구매, 제품의 차별성, 실제 시장 우위는 별개의 판단이다. 이번에는 사용자 수, 유입 비용, 재방문율, 결제 전환이나 학습 효과를 측정하지 않았다. 성공 확률을 수치로 제시할 근거도 없다.

App Store의 [동명 codefit](https://apps.apple.com/jp/app/codefit/id6805557220)은 공개 설명상 문답과 반복 복습 중심이다. 현재 Codefit의 실행/수정 흐름과 차이가 있다. 상대의 실제 앱 전체를 조작하거나 시장 점유율을 측정하지 않았으므로 제품 전체의 우열을 단정하지 않는다.

실제 대체재는 동명 제품에 한정되지 않는다. [Replit Learn](https://learn.replit.com/)은 AI와 바이브 코딩 학습을, [CodeCrafters](https://codecrafters.io/)는 실제 시스템을 구현하는 도전을 제공한다. 사용자가 평소 쓰는 AI 도구에 설명과 수정 요청을 하는 선택지도 있다. ‘동명 서비스보다 기능이 많다’만으로 시장에서 선택받을 이유가 성립하지 않는다.

초기 사용자 범위를 ‘AI로 웹/앱을 만들어 봤지만 저장 실패, 접근 권한과 요청 순서를 스스로 설명하거나 검사하기 어려운 사람’으로 좁히는 편이 현재 입문 실습과 잘 맞는다. 이는 검증할 고객 가설이며 이미 확인된 고객군은 아니다. 이 사람에게 짧은 실습이 실제 검증 습관을 남기는지 확인해야 한다.

콘텐츠와 UI를 계속 늘리기 전에 20~30명의 탐색적 사용자 실험으로 첫 미션 완료, 일주일 안의 자발적인 재방문, 새로운 변형 상황에서의 잘못된 수정안 식별, 기존 AI 도구 대신 선택한 이유를 살펴보는 것을 권한다. 표본 규모는 실행 가능한 제안이며 업계 표준이나 통계적 검증을 보장하는 수치가 아니다. 미션 완료율만으로 학습 효과를 주장하지 않는다.

### 유지해도 되는 조건과 변경의 이점

`codefit.app`은 재조회에서도 Vercel 1년 USD 9.99로 등록 가능했다. 저렴한 도메인을 쓰며 수요를 검증하거나 포트폴리오를 운영하는 선택은 합리적이다. 동명 서비스가 존재한다는 사실만으로 실패를 예상할 수는 없다.

장기적인 공개 브랜드를 새로 키울 때에는 여전히 변경을 권한다. 동일 분야에서 같은 이름을 써야 하는 명확한 사업상 이득이 확인되지 않았고, 자체 인지도가 높다는 증거도 이번 조사에는 없다. 이름을 바꾸면 검색과 소개에서 구별하기 쉬워질 수 있지만, 재방문과 학습 효과를 대신 만들어 주지는 않는다. 기존 사용자 기반이 크다면 이 판단의 전환 비용을 다시 계산해야 한다.

### 추천 후보와 제외한 이름

브랜드 판단의 1순위는 **앱리허설 / AppRehearsal**이다. 예제 앱에서 예상하고 실험한 뒤 실제 상황에 적용한다는 의미가 서비스와 직접 연결되고, 코드를 모르는 사람도 배제하지 않는다. 한국어는 네 음절이며 ‘앱의 원리부터, AI 코드 이해까지’라는 부제를 붙일 수 있다. 영어 철자가 길고 일반 앱 QA/테스트 도구로 오인할 수 있다는 비용이 있다. 선호도 조사로 검증된 이름은 아니다.

후보의 정확한 영문/한글 명칭 검색에서 명확한 동명 학습 서비스는 발견하지 못했다. 미검색 서비스와 유사 상표까지 없다는 뜻은 아니다. 도메인 견적은 갱신 가격이나 세금 포함 최종 결제액을 보장하지 않는다.

`BuildWhy`는 [BuildWHY Technologies](https://buildwhy.com/)라는 기술 회사 홈페이지가 확인돼 제외했다. `CodeWhy`도 [Code Why](https://codewhy.in/)와 [코딩 튜토리얼 사이트](https://www.codewhy.net/c-c-tutorial.html)가 있어 제외했다. 도메인 확장자 하나가 남아 있다는 이유만으로 새 이름을 추천하지 않았다. `ReasonFit`, `AppReason`, `ReasonBuild`도 조회했지만 현재 이름보다 명확하게 낫다는 판단이 서지 않아 추천 후보에 포함하지 않았다.

이번 후속 작업도 조사와 문서 정리만 수행했다. 도메인 구매, 서비스 이름 변경, 상표 등록 및 코드 배포는 하지 않았다.
