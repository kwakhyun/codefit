# 기능 소개 배너

2026-09-17. 네 가지 기능에 맞춘 이미지와 문구를 제작했다. 레이아웃과 동작은 [입문 트랙 설계](../beginner-training.md)에 설명한다.

## 문구 조사와 적용

[코드잇 메인](https://www.codeit.kr/), [인프런 메인](https://www.inflearn.com/), [Codecademy 메인](https://www.codecademy.com/)의 공개 페이지를 확인했다. 코드잇은 짧은 단위의 학습과 실습을, 인프런은 입문 수준과 학습 주제를, Codecademy는 직접 해볼 수 있는 활동과 시작 경로를 드러낸다. 이를 참고해 코드핏에서는 추상적인 성장 표현을 줄이고 눈앞의 상황, 직접 할 행동과 실제 제공 기능을 설명했다. 다른 서비스의 문구나 성과 수치는 가져오지 않았다. 사용자 선호를 측정한 실험 결과는 아니다.

| 기능         | 적용한 제목                                     | 연결               |
| ------------ | ----------------------------------------------- | ------------------ |
| 앱의 원리    | 앱이 작동하는 원리를 기초부터 배워보세요        | `/learn`           |
| 앱 오류 해결 | 앱 오류를 찾고 수정하는 방법을 익혀보세요       | `/learn#labs`      |
| 코드 이해    | AI가 작성한 코드를 읽고 분석해 보세요           | `/handoff`         |
| 문제 생성    | 원하는 분야와 난이도로 코딩 문제를 만들어보세요 | 문제 생성 대화상자 |

‘내 판단으로 완성하는 힘’, ‘읽을 수 있는 코드에서, 설명할 수 있는 코드로’와 같은 추상적인 문장을 바꿨다. 문제 생성은 로그인과 하루 3회 제한을 설명하며, 입문 실습은 연습용 앱이라는 범위를 유지한다. 제목과 설명은 실제 HTML 텍스트여서 화면 크기에 따라 줄바꿈되며 검색, 번역과 접근성 도구에서 읽을 수 있다.

사용자가 질문형 문구도 어색하다고 지적해 다시 수정했다. 배너 제목은 학습 대상과 할 일을 바로 설명하며, 설명에는 데이터 저장, 오류 재현, 코드 분석 등 실제 활동을 담았다. 기능 이름은 ‘앱 오류 해결 실습’으로 통일하고 입문 화면, 실습 안내, 메타데이터와 README에도 반영했다. 처음 사용자를 위한 안내와 동작을 예상하는 학습 질문은 구분해, 학습에 필요한 질문과 기술 용어는 유지했다.

## 이미지

기본 제공 `image_gen` 도구로 각각 생성했다. [전체 프롬프트](feature-banner-prompts.json)에 매체, 구도, 색과 주제를 기록했다. 외부 서비스의 이미지나 로고를 복제하지 않았다.

| 파일                                           | 주제                                    |    WebP 크기 |
| ---------------------------------------------- | --------------------------------------- | -----------: |
| `public/images/features/app-foundations.webp`  | 메모 화면, 서버와 데이터 저장소의 연결  | 23,176바이트 |
| `public/images/features/debug-lab.webp`        | 중복 메모를 살피는 확대경과 수리 도구   | 32,654바이트 |
| `public/images/features/read-code.webp`        | 코드에서 결과로 이어지는 흐름           | 33,792바이트 |
| `public/images/features/practice-builder.webp` | 난이도를 고르고 연습 카드를 만드는 기계 | 37,554바이트 |

검은 배경, 아이보리색 레트로 컴퓨터와 각 기능의 강조색을 사용했다. 원본 1536×1024 PNG에서 웹용 960×640 WebP로 변환했다. 네 파일 합계는 127,176바이트다. 원본은 로컬 생성 디렉터리에 보존하며 앱은 저장소에 포함된 WebP만 참조한다.

이미지는 보조 장식이므로 빈 대체 텍스트를 사용하고, 기능 설명과 동작 버튼은 이미지와 분리했다. 그림의 비율은 `object-fit: contain`으로 유지하고 이미지 영역은 데스크톱 300px, 모바일 180px 높이를 예약한다. 너비에 의존한 높이 계산이 WebKit의 숨은 그리드 항목에서 늦게 반영되던 문제를 피하기 위한 선택이다. `next/image`로 이미 압축된 파일을 그대로 제공한다. 첫 그림은 즉시 로드하고 나머지는 브라우저의 지연 로딩을 요청한다. 네 슬라이드를 한 줄의 Flex 항목으로 배치하고 상대 위치로 같은 자리에 겹쳐, 가장 긴 내용의 높이를 예약한다. 비활성 슬라이드는 포커스와 접근성 트리에서 제외한다. 문구 수정 후 WebKit의 겹친 Grid 행이 화면 폭 변경 전 높이를 유지하다 단계적으로 줄어드는 현상을 재현해 배치를 바꿨다. 고정된 텍스트 높이나 글자 잘라내기는 사용하지 않는다. 전환 애니메이션은 위치만 바꾸며 글자 대비를 낮추지 않는다.

문제 생성은 페이지 이동이 아니라 기존 생성 창을 여는 버튼이다. 같은 메인 화면의 쿼리 문자열만 바꾸는 링크는 초기 상태를 다시 읽지 않아 창이 열리지 않는 것을 실제 클릭으로 확인했고, 기존 생성 핸들러를 배너까지 전달하도록 수정했다.

Safari는 마우스로 누른 버튼에 포커스를 주지 않아 생성 창을 닫을 때 앞서 선택했던 슬라이드 버튼으로 돌아갔다. 생성 버튼을 활성화할 때 포커스를 지정해 창의 복귀 위치를 명확히 했다. 키보드나 마우스 어느 쪽으로 시작해도 생성 버튼으로 돌아온다.
