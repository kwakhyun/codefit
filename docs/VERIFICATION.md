## WebKit의 편집기 준비 시점 경합 — 2026-09-18

CI 실행 `35290769184`의 최초 실패와 재시도 trace를 확인했다. AI 요청은 원본 코드로 전송됐고, 테스트가 Monaco 모델에 정답 코드를 넣은 뒤에도 서버 PUT에는 원본 코드와 새 메모만 있었다. 따라서 AI 질문의 스냅샷과 앱의 현재 코드가 같아 ‘코드가 바뀌었습니다’ 안내가 나오지 않았다. 수정 전 로컬 WebKit 단독 실행은 통과했으므로 로컬에서 항상 재현되는 결함이라고 표현하지 않는다.

`@monaco-editor/react`는 모델을 만든 뒤 준비 상태를 커밋하고 effect에서 onMount와 변경 구독을 연결한다. 기존 E2E 헬퍼는 모델 존재만 기다려 이보다 먼저 setValue를 호출할 수 있었다. 편집기 모델 읽기만으로는 React/자동 저장에 반영되지 않은 입력도 정상처럼 보였다.

- `e2e/editor-helpers.ts`: 앱의 onMount에서 등록하는 `codefit.save` 액션을 가진 편집기를 기다리고 그 인스턴스로 읽기/쓰기를 수행한다. 임의 sleep, 재시도 횟수 증가 또는 제품 코드의 판정 완화는 추가하지 않았다.
- `e2e/understanding.spec.ts`: AI 요청이 원본 코드를 사용했는지 확인하고, 대기 중 수정 코드가 저장된 뒤에만 모의 응답을 해제한다. 응답 후 저장된 코드와 새 메모도 함께 확인한다. 기존 변경 안내 및 오프라인 복구 단언은 유지한다.
- 관련 4개 시나리오를 세 브라우저로 검사했다. 첫 실행은 9개 통과, 백업 복원 3개가 기존 로컬 테스트 DB에 누적된 가져오기 한도로 실패했다. 기존 DB와 실패 자료를 보존한 뒤 새 테스트 DB에서 백업 3개를 재실행해 모두 통과했다. 한도 정책은 변경하지 않았다.
- 실패했던 WebKit 시나리오는 추가로 **5회 반복해 모두 통과**했다(39.5초). 변경 파일 ESLint, TypeScript 및 포맷/차이 검사를 통과했다. 전체 회귀, 유료 AI 호출, 운영 DB 변경은 수행하지 않았다. 원격 CI의 수정 후 결과는 아직 검증하지 않았다.

동일 로컬 프로덕션 빌드와 격리 SQLite를 사용했다. CI 원본은 `artifacts/ci-understanding/`, 실행 로그는 `artifacts/understanding-before.log`, `artifacts/editor-ready-regression.log`, `artifacts/editor-ready-backup.log`, `artifacts/editor-ready-webkit-repeat.log`에 보존한다. 이 변경은 테스트 동기화 수정이며 서비스 응답 속도 개선 수치가 아니다.

## 이용 상태 카드와 배너 버튼 — 2026-09-18

사이드바의 의미 없는 F 아바타와 상태 점을 제거했다. 비로그인 상태는 기록 안내 및 로그인 버튼으로, 로그인 상태는 사용자 이름과 계정 기록 안내로 표시한다. 중복된 하단 게스트 로그인 링크는 제거하고 회원 프로필 링크는 유지했다. 배너의 초 표시와 재생/일시정지 버튼을 제거하고 CTA를 네 배너의 민트/앰버/블루/바이올렛 색상에 맞췄다. 진행 막대, 이전/다음, 호버/키보드 조작 시 전환 중지와 모션 감소 설정은 유지한다.

## 최신 검증 요약 — 2026-09-18

이번 실행은 전체 화면과 핵심 기능을 검토해 달라는 요청에 따라 진행했다. 현재 구성은 코딩 문제 24개, 입문 미션 29개, 5개 서비스 분야다. [UI 변경과 실제 화면](design/release-ui-review.md)에 문제, 영향과 구현 위치를 정리했다. 아래 이전 기록은 각 실행 당시의 기능/데이터 규모이며 현재 결과와 합산하지 않는다.

- **단위 및 SQLite: 166개 통과, PostgreSQL 23개 건너뜀**(2.64초). 로컬에 테스트용 PostgreSQL/실행 중 Docker가 없어 DB 변수를 설정하지 않았다. 운영 DB로 대체하지 않았다. GitHub Actions는 별도 PostgreSQL 16 서비스에서 같은 계약을 실행하도록 구성되어 있으며 이 로컬 결과에 CI 결과를 포함하지 않는다.
- **전체 브라우저: 88개 시나리오 × 3개 브라우저 = 264개 실행, 261개 통과, 3개 실패**(18.0분). 실패는 모두 같은 실습 검사에서 삭제된 안내 문구를 기대한 단언이었다. 기대값을 현재의 빈 초기 기록으로 수정했으며 앱 오류를 감추기 위해 검사 자체를 제거하지 않았다.
- **최종 빌드 후 영향 범위 재검증: 10개 시나리오 × 3개 브라우저 = 30개 모두 통과**(2.7분). 위 실패 3개, 로그인 안내, 가이드 선택/통신/키보드 조작, 새 실습 기본 축소 상태, 11개 공개 화면 계열과 프로젝트 질문/결과를 포함한다. 전체 실행과 별도 실행이며 294개가 한 번에 통과했다고 표현하지 않는다. 미해결 테스트 실패는 없다.
- 전체 핵심 흐름에는 29개 입문 실습, AI 코드 분석과 실행, 문제 검색, 북마크, 힌트/정답, 자동 저장, 다중 탭 충돌, 오프라인 복구, 제출본 복원, 백업, 계정 격리/프로필/로그아웃, 사용량 한도, 프로젝트 질문/평가/삭제, 가이드, 음성 입력 이벤트가 포함됐다. AI 응답은 모의 데이터, 로그인은 격리 DB의 테스트 세션으로 검사했다.
- **API 통합 검사 통과**: 공개 진입, 사용자 격리, 입력/Origin 검사, 저장, 힌트/정답, 백업 복원과 생성 로그인 제한을 격리 서버에서 확인했다. 최종 프로덕션 빌드와 TypeScript, ESLint, Prettier, Knip 및 문서 로컬 링크 검사도 통과했다.
- UI는 320/390/768px 가로 넘침과 390px axe WCAG 2 A/AA 및 2.1 AA 태그를 검사했다. 데스크톱/모바일 캡처를 직접 보고 가이드의 답안 가림과 메뉴 정렬을 수정했고, 별도 브라우저에서 선택 메뉴의 키보드 열기/선택을 조작했다. 자동 접근성 검사, 화면 시각 검토, 키보드 조작을 구분한다. 실제 휴대폰과 스크린 리더 청취는 검사하지 않았다.
- 로컬 로그인이 비활성인 이유는 OAuth 환경 변수 미설정이었다. 3010 사용자 미리보기와 3012 자동 테스트 서버를 분리하고 로컬 로그인 안내와 운영 링크를 추가했다. 운영 workspace의 제공자 `google`, `github` 활성 상태(HTTP 200)는 읽기만 확인했다. 실제 제공자 본인 인증/콜백은 이번에 다시 수행하지 않았다.
- 환경: Apple M2/16GB, macOS 26.6.2, Node 22.21.0, Next 16.3.4 프로덕션 빌드, Chromium 153.0.8010.12/Firefox 155.0/WebKit 26.6. 별도 SQLite, 로컬 네트워크, CPU/네트워크 감속 없음. 1회 전체 실행과 최종 영향 범위 1회 재실행이다. 소요 시간은 테스트 실행 시간이며 서비스 성능 또는 실사용자 지표가 아니다.
- 이번 검증의 유료 AI 호출과 운영 DB 쓰기는 0회다. 실제 음성 인식, 모델 품질 재평가와 부하/성능 비교는 범위에 포함하지 않았다. 원본은 로컬 `artifacts/full-unit.log`, `artifacts/full-e2e.log`, `artifacts/release-full-run/`, `artifacts/release-targeted.log`, `artifacts/ui-refresh/`에 남긴다. 현재 README에는 서비스 소개, 모델/한도와 기록 보관 범위를 반영했다.

## 화이트 실습 앱, 선택형 이유와 음성 입력 — 2026-09-18

### 확인한 동작

아홉 미션을 예상 작성부터 문제 재현, 불완전한 수정안 비교, 각 동작 검사, 응용과 완료 후 새로고침 복원까지 실행했다. 코드 입력이나 AI 호출 없이 끝낼 수 있다. 단계별 힌트, 기록 내보내기, 관찰 초기화 후 복구, 모바일 입력과 키보드 이동도 확인했다.

두 탭의 서로 다른 기록과 재충돌, 충돌 해결 중 새 입력, 오프라인 작성 후 복귀와 다른 게스트의 기록 격리를 검사했다. 늦은 AI 응답은 현재 입력을 보존하며, 같은 입력의 실패 재시도는 같은 ID를 쓰고 변경된 입력은 새 ID를 쓴다. 서버에서 잘못된 미션 기록, 워크스페이스 불일치와 근거 없는 AI 요청을 거절한다.

axe WCAG 2 A/AA 및 2.1 AA 자동 검사와 Playwright의 키보드/포커스 검사를 구분한다. 별도로 실제 인앱 브라우저에서 데스크톱과 모바일 화면, 생성 창 열기/닫기와 콘솔 오류를 확인했다. 스크린 리더 수동 청취와 학습자 사용성 실험은 하지 않았다. AI 문장 품질과 장기 학습 효과도 아직 측정하지 않았다.

### 발견한 문제와 수정

첫 전체 회귀는 **118개 통과, 5개 실패**였다(11.7분). 메인 문구 변경으로 기존 계정 테스트 3개가 오래된 제목을 찾았고 선택자를 갱신했다. Firefox의 배너 애니메이션에서 글자 대비가 낮아져 투명도 전환을 제거했다. WebKit에서는 메모 변경 후 AI 재시도 ID 검사 한 건이 실패했다. 별도 5회 재현에서는 통과했지만, 전환 제목에 중복된 지연 포커스가 있음을 확인했다. 포커스를 React의 화면 반영 시점에 한 번만 처리하고 메모 값과 초점 검사를 추가했다.

**조작 검사**: Playwright 입력 이벤트로 단계 버튼의 키보드 활성화와 포커스 이동, 메모 입력, 충돌 비교와 복원/취소를 확인했다. agent-browser로 실제 로컬 화면을 열어 렌더링과 콘솔 오류를 확인하고 데스크톱/모바일 스크린샷을 직접 검토했다. 스크린 리더를 사용한 수동 청취 검사는 하지 않았다.

### 검사 중 수정한 점과 남은 한계

- 최초 백업 검사 429는 이전 테스트의 접속망 가져오기 한도가 남아 있었기 때문이다. 제한을 제거하는 제품 변경 없이 과거 테스트 DB를 보존하고 새 테스트 DB에서 통과했다.
- 새 초기화/오류 테스트가 모든 `role=alert`를 선택하면서 Monaco와 Next.js의 숨은 알림까지 매칭했다. 실제 `.workspace-error`로 범위를 좁혀 테스트를 수정했다. 이 실패를 제품 데이터 유실로 해석하지 않는다.
- 정답 공개와 제출본 복원, 초기화 안내에 메모 보존/교체 범위를 명시했다. 시작 코드 초기화는 메모를 유지한다.
- 실제 AI 첫 검사 13건은 예상과 8건 일치, 메모를 보완한 참고 6건은 5건 일치했다. 오류 시작 코드 6건과 지시문 공격 1건은 모두 거절됐다. 참고 코드 자체는 자동 테스트를 통과해도 설명 누락으로 AI 리뷰에서 거절될 수 있다. 세부 사유와 비용은 [설계 문서](engineering.md#실제-ai-검토에서-발견한-문제)와 원본 보고서에 기록했다. 일반 리뷰의 기존 평가 수치를 인수인계 정확도로 재사용하지 않는다.
- 변형 과제는 코드 구조와 상황을 바꾸되 함수 계약을 공유하는 제한된 재훈련이다. 7일 경계는 가상 날짜와 제출 기록으로 검증했으며 실제 7일간 학습 효과를 관찰하지 않았다.
