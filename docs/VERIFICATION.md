## 서비스 전체 문구 점검과 커밋 전 회귀 검증 — 2026-09-18

메인, 목록과 학습 기록, 로그인/프로필, 입문 실습, 코드 이해 훈련, 풀이/검토, 설정/도움말과 오류 안내를 점검했다. 화면 목적과 사용자의 다음 행동을 드러내도록 문장을 수정하고, 기능 명칭을 맞췄다. 생성 횟수와 개인 기록의 범위, 코딩 백업에 입문 실습 기록이 포함되지 않는다는 제한도 화면과 README에 명시했다. [문구 변경 기록과 모바일 화면](design/service-copy.md)을 참고한다.

- 단위/SQLite **106개 통과**, 격리 PostgreSQL 서버 부재로 **21개 미실행**. 역사적 AI 평가 사례와 지문을 그대로 유지했으며 관련 **21개 테스트도 별도로 통과**했다. 서로 다른 실행의 수를 합산하지 않는다.
- 프로덕션 빌드에서 전체 **42개 시나리오 × Chromium/Firefox/WebKit = 126개가 한 번의 실행에서 모두 통과**했다(9.3분). 기존 풀이, 계정 격리, 저장 충돌/오프라인/복원과 신규 입문 미션, 배너 전환 및 기능 연결을 포함한다.
- 첫 실행은 새 문구를 반영하지 않은 선택자 때문에 20개 통과, 1개 실패 후 중단했다(1개 중단, 104개 미실행). 생성 한도 안내와 돌아가기 링크 선택자를 수정한 뒤 위 전체 실행을 수행했다. 실패 자료와 최종 보고서는 로컬 `artifacts/service-copy-*`에 보존했다.
- 환경은 아래 입문 검증과 동일한 Apple M2/16GB, macOS 26.6.2, Node 22.21.0, Next 16.3.4 프로덕션 빌드, 격리 SQLite와 시드 24개/미션 9개다. 브라우저별 전체 실행 1회이며 CPU/네트워크 감속은 없다. 운영 DB 쓰기와 새 유료 AI 호출은 0회다.

- 최종 소스로 프로덕션 빌드와 TypeScript 검사를 다시 통과한 뒤 훈련 진입/모바일/접근성 시나리오를 세 브라우저에서 재확인해 **3개 모두 통과**했다(24.1초).

## 배너와 입문 안내 문구 후속 수정 — 2026-09-17

질문형 홍보 문구를 학습 대상과 실제 활동을 설명하는 문장으로 바꾸고, ‘앱 오류 해결 실습’ 명칭을 배너, 입문 화면, 도움말과 문서에 맞췄다. 예상을 묻는 학습 질문과 기존 저장 형식은 유지했다.

- 프로덕션 빌드와 TypeScript, 변경 파일 ESLint/포맷 검사 통과. 입문 학습 단위 테스트 **12개 통과**.
- `e2e/beginner.spec.ts`의 기초/오류 해결 대표 미션, 모바일 키보드 진입, 배너 전환과 네 기능 연결을 Chromium, Firefox, WebKit에서 실행해 최종 **15/15 통과**(1.5분). 배너는 320/390/768/1440px 폭, 이미지 로드, 높이 유지와 가로 넘침, axe 검사, 생성 창 포커스 복귀를 포함한다. 단위 테스트나 과거 전체 회귀와 합산하지 않는다.
- 첫 실행은 **14개 통과, 1개 실패**였다. WebKit에서 화면 폭 변경 후 배너 높이가 691.09→652.09→624.34px로 줄어들었다. 실제 글자 크기는 갱신됐지만 겹친 Grid 행의 높이가 남아 있었다. 숨김 방식과 내부 배치 변경만으로는 해결되지 않아, 바깥 배치를 Flex로 바꾸고 각 슬라이드를 상대 위치로 겹쳤다. WebKit 2회 반복 통과 후 위 최종 검사를 실행했다. 검사 허용치를 늘리지 않았다.
- 이전 절과 같은 로컬 프로덕션 환경, 격리 SQLite와 시드 데이터를 사용했다. CPU/네트워크 감속, 운영 DB 쓰기와 유료 AI 호출은 없다. 자동 접근성 검사와 별도로 인앱 브라우저에서 데스크톱/모바일 문구를 확인하고 화면 자료를 갱신했다. 사용자 대상 문구 선호도 실험은 아니다.

## 입문 실습과 기능 소개 배너 — 2026-09-17

기존 변경은 `43eb771e1cf3aa7e40dd6c9e626e7c07364f60b8`로 커밋하고 GitHub main에 푸시했다. 이후 기초 미션 6개, 고장 난 앱 실습 3개, 선택적 AI 질문과 기능 소개 배너를 로컬에서 구현했다. 이 절은 신규 구현을 커밋하거나 배포하기 전에 수행한 최초 로컬 검증 기록이다. [기능과 저장 설계](beginner-training.md), [배너 문구 조사와 이미지 제작](design/feature-banner.md), [실행 요약](../reports/beginner-validation.json)을 함께 확인할 수 있다.

### 환경과 검사 범위

- Apple M2, 메모리 16GB, macOS 26.6.2 arm64, Node 22.21.0, Next 16.3.4 프로덕션 빌드. 기존 시드 문제 24개와 새 고정 미션 9개를 사용했다.
- Playwright 1.63.0의 Chromium, Firefox, WebKit. 기본 데스크톱 1280×720, 모바일 390×844, 배너 320/390/768/1440px 폭. CPU와 네트워크 인위적 감속은 없고, 오프라인/지연/AI 오류는 해당 테스트에서 주입했다.
- 격리 SQLite, 가상 게스트와 테스트 계정을 사용했다. 운영 DB에 쓰지 않았으며 서비스의 OpenAI API 유료 호출은 0회다. AI 코치 응답은 모의 처리했다. 배너 이미지 4장은 별도의 기본 제공 이미지 생성 도구로 제작했다.
- 단위/SQLite **106개 통과**, PostgreSQL **21개 미실행**. PostgreSQL용 공통 계약을 추가했지만 격리 서버가 없어 실행하지 않았다. 운영 DB로 대체하지 않았다.
- 프로덕션 빌드, TypeScript, ESLint, 미사용 코드와 포맷 검사 통과. 원본 결과는 로컬 `artifacts/beginner-*`, `playwright-report/`와 `test-results/`에 보관한다.

### 확인한 동작

아홉 미션을 예상 작성부터 문제 재현, 불완전한 수정안 비교, 각 동작 검사, 응용과 완료 후 새로고침 복원까지 실행했다. 코드 입력이나 AI 호출 없이 끝낼 수 있다. 단계별 힌트, 기록 내보내기, 관찰 초기화 후 복구, 모바일 입력과 키보드 이동도 확인했다.

두 탭의 서로 다른 기록과 재충돌, 충돌 해결 중 새 입력, 오프라인 작성 후 복귀와 다른 게스트의 기록 격리를 검사했다. 늦은 AI 응답은 현재 입력을 보존하며, 같은 입력의 실패 재시도는 같은 ID를 쓰고 변경된 입력은 새 ID를 쓴다. 서버에서 잘못된 미션 기록, 워크스페이스 불일치와 근거 없는 AI 요청을 거절한다.

axe WCAG 2 A/AA 및 2.1 AA 자동 검사와 Playwright의 키보드/포커스 검사를 구분한다. 별도로 실제 인앱 브라우저에서 데스크톱과 모바일 화면, 생성 창 열기/닫기와 콘솔 오류를 확인했다. 스크린 리더 수동 청취와 학습자 사용성 실험은 하지 않았다. AI 문장 품질과 장기 학습 효과도 아직 측정하지 않았다.

### 발견한 문제와 수정

첫 전체 회귀는 **118개 통과, 5개 실패**였다(11.7분). 메인 문구 변경으로 기존 계정 테스트 3개가 오래된 제목을 찾았고 선택자를 갱신했다. Firefox의 배너 애니메이션에서 글자 대비가 낮아져 투명도 전환을 제거했다. WebKit에서는 메모 변경 후 AI 재시도 ID 검사 한 건이 실패했다. 별도 5회 재현에서는 통과했지만, 전환 제목에 중복된 지연 포커스가 있음을 확인했다. 포커스를 React의 화면 반영 시점에 한 번만 처리하고 메모 값과 초점 검사를 추가했다.

그다음 입문/계정/코드 이해 집중 검사는 **65개 통과, 1개 실패**였다(4.8분). 실패는 WebKit에서 320px → 390px로 바꿀 때 첫 슬라이드 높이만 17.34px 작게 측정된 경우다. 폰트/이미지 로딩과 프레임 대기를 추가해도 반복됐으므로 검사 허용치를 높이지 않았다. 이미지 영역을 화면 폭에 의존한 높이 대신 데스크톱 300px, 모바일 180px로 예약하고 원본 비율은 `object-fit`으로 유지하도록 수정했다.

실제 클릭 확인에서는 문제 생성 배너가 쿼리 문자열만 바꾸고 창을 열지 않는 문제를 발견해 기존 생성 핸들러를 연결했다. Safari에서 마우스 클릭이 버튼에 포커스를 주지 않는 동작도 반영해, 생성 창을 닫으면 누른 버튼으로 돌아오게 했다. 네 배너의 실제 진입 경로 검사를 추가했다. 실패 추적 자료는 삭제하지 않고 `artifacts/beginner-full-first-*`, `beginner-final-candidate-*`, `beginner-banner-resize-repro-*`, `beginner-banner-ratio-*`에 보관했다.

최종 빌드에서 **배너 2개 시나리오 × 세 브라우저 × 2회 = 12개 모두 통과**했다(2.0분). 이미지 로드, 네 가지 폭에서 슬라이드 높이 유지, 가로 넘침, 키보드 일시 정지, 동작 줄이기, 각 기능 진입과 생성 창 포커스 복귀를 포함한다. 네 장 각각의 axe 검사도 통과했다. 이전 집중 검사의 65개 통과와 이번 12개는 서로 다른 실행이며 전체 회귀가 한 번에 모두 통과한 것으로 합산하지 않는다. 이전 전체 회귀에서 일반 풀이, 인수인계, 코드 충돌 등 나머지 57개는 통과했고 마지막 배너 수정으로 해당 로직을 변경하지 않았다.

화면: [데스크톱 배너](images/beginner-home.png), [모바일 배너](images/beginner-home-mobile.png), [기초 코스](images/beginner-course.png), [관찰 실습](images/beginner-observe.png). 이미지 네 파일은 합계 127,176바이트다. 이 값은 정적 파일 크기이며 전후 로딩 성능이나 운영 사용자 지표가 아니다.

3. 두 탭의 충돌에서 코드 및 메모 비교, 비교 중 메모 수정, 서버 재변경으로 재충돌, 명시적 저장 후 편집기 포커스 복귀.
4. 리뷰 대기 중 새 메모 보존, 제출 시점 스냅샷과 현재 초안 구분, 제출본 복원 및 변경 취소.
5. 부족한 기준과 7일 재도전 안내, 변형 과제에 답/메모를 미리 복사하지 않음, 백업 라운드트립과 개인 API의 no-store.
6. 시작 코드 초기화 시 메모 유지, 실행 취소, AI 오류 때 코드와 모든 메모 보존.

**자동 접근성**: axe의 WCAG 2 A/AA 및 2.1 AA 규칙으로 대시보드, 모바일 입력 화면, 충돌 비교와 리뷰 결과를 검사했다. 위반 0건인 자동 검사와 전체 접근성 적합성 인증은 구분한다.

**조작 검사**: Playwright 입력 이벤트로 단계 버튼의 키보드 활성화와 포커스 이동, 메모 입력, 충돌 비교와 복원/취소를 확인했다. agent-browser로 실제 로컬 화면을 열어 렌더링과 콘솔 오류를 확인하고 데스크톱/모바일 스크린샷을 직접 검토했다. 스크린 리더를 사용한 수동 청취 검사는 하지 않았다.

### 검사 중 수정한 점과 남은 한계

- 최초 백업 검사 429는 이전 테스트의 접속망 가져오기 한도가 남아 있었기 때문이다. 제한을 제거하는 제품 변경 없이 과거 테스트 DB를 보존하고 새 테스트 DB에서 통과했다.
- 새 초기화/오류 테스트가 모든 `role=alert`를 선택하면서 Monaco와 Next.js의 숨은 알림까지 매칭했다. 실제 `.workspace-error`로 범위를 좁혀 테스트를 수정했다. 이 실패를 제품 데이터 유실로 해석하지 않는다.
- 정답 공개와 제출본 복원, 초기화 안내에 메모 보존/교체 범위를 명시했다. 시작 코드 초기화는 메모를 유지한다.
- 실제 AI 첫 검사 13건은 예상과 8건 일치, 메모를 보완한 참고 6건은 5건 일치했다. 오류 시작 코드 6건과 지시문 공격 1건은 모두 거절됐다. 참고 코드 자체는 자동 테스트를 통과해도 설명 누락으로 AI 리뷰에서 거절될 수 있다. 세부 사유와 비용은 [설계 문서](engineering.md#실제-ai-검토에서-발견한-문제)와 원본 보고서에 기록했다. 일반 리뷰의 기존 평가 수치를 인수인계 정확도로 재사용하지 않는다.
- 변형 과제는 코드 구조와 상황을 바꾸되 함수 계약을 공유하는 제한된 재훈련이다. 7일 경계는 가상 날짜와 제출 기록으로 검증했으며 실제 7일간 학습 효과를 관찰하지 않았다.

## 저장 경합과 편집 성능 — 2026-09-14

기준 커밋 `1eeefc7c3884df3a8061a98cbf8be8fec92a7cff`와 작업 시작 HEAD가 같음을 확인했습니다. 이후 변경으로 해결되어 제외한 항목은 없습니다. 기존 Monaco 지연 로딩, 저장 중 재입력 보존, 제출본 복원/취소와 계정 검사는 재사용했습니다.

- **단위/저장소 65개 통과**: SQLite와 PostgreSQL 공통 리비전 계약, 만료된 실행의 성공/실패/예약 변경 차단, 요청 내용 지문, 동일 결과 재요청, 생성 한도, 최종 완료 단계의 강제 오류와 전체 롤백, 기존 스키마 업그레이드, 브라우저 저장 공간 실패를 검사했습니다.
- **PostgreSQL 18.6, 다중 연결 검증**: 운영과 다른 Preview DB의 임시 스키마에서 실행했습니다. fixture 쓰기 전 `current_schema()`를 검사하고 종료 후 삭제했습니다. 동시에 확보한 연결의 backend PID가 5개임을 확인했으며, 동시 코드 갱신과 같은 실행의 결과 저장은 각각 한 번만 성공했습니다. CI 설정은 별도의 PostgreSQL 16 서비스를 사용합니다. 이번 로컬 실행을 CI 통과로 표현하지 않습니다.
- **브라우저 42개 조합 확인**: Chromium 153.0.8010.12, Firefox 155.0, WebKit 26.6에서 각 14개 시나리오. 최종 전체 실행은 41개 통과, Firefox 제출 복원 한 건은 테스트가 Monaco 지연 로딩 완료 전에 모델을 읽어 실패했습니다. 준비 상태 대기로 테스트를 수정하고 해당 시나리오를 다시 실행해 통과했습니다. 그 이전 실행에서 발견한 WebKit 설정 창의 포커스 복귀 문제는 실제 버튼 포커스 처리로 수정하고 최종 실행에서 통과했습니다.
- **실제 조작 검증**: Playwright의 브라우저 입력 이벤트로 두 로그인 탭의 지연 저장, 다른 기기의 오프라인 충돌/재접속/재진입, 재충돌, 응답 대기 중 입력, 비교 영역 키보드 편집, 완료 후 편집기로 포커스 복귀를 확인했습니다. 기존 검색 응답 순서, 북마크/힌트의 코드 보존, 백업/제출본 복원과 변경 취소, 계정 전환도 포함합니다. 데스크톱과 390×844 폭에서 가로 넘침을 검사했습니다.
- **자동 접근성 검사**: axe의 WCAG 2 A/AA 및 2.1 AA 태그로 기본 화면과 새 충돌 화면을 검사해 위반이 없었습니다. 위의 입력/포커스 테스트와 구분합니다. 실제 화면 이미지도 검토했으나 사람의 스크린리더 사용성 평가나 모든 보조 기기 검증을 완료한 것은 아닙니다.
- **계정 데이터 노출 검사**: 초기 workspace에 함께 전달하는 상세가 `no-store`인지, 다른 세션에는 초안/힌트/정답이 노출되지 않는지, 기준 리비전 없는 PUT이 428인지 검사했습니다. AI 키를 비운 환경에서 같은 요청 재시도와 다른 코드의 ID 재사용(409)을 구분했습니다.
- **성능 검증**: 전후 동일 프로덕션 조건에서 각 화면/기기 조건을 5회씩 측정했습니다. 목록 표시 확인 중앙값은 데스크톱 942.8→836.0ms, 제한 모바일 2,127.1→1,579.6ms였습니다. 편집기 준비의 이득은 확인하지 못했습니다. 모바일 입력 지연의 큰 편차는 두 빌드를 교대한 5쌍의 별도 실험으로 조사했으며 원본 수치와 한계도 보존합니다.
- **유료 AI 호출 0회, 운영 DB 쓰기 0회**: 외부 제공자의 정확히 한 번 호출을 보장하지 않습니다. 이번 검증은 저장소와 API 계약 및 UI 검증이며, 아래 과거 유료 AI 검증을 새로 수행한 것으로 세지 않았습니다.

## 검증 범위와 한계

AI 검토는 정적 피드백이며 제출 코드를 실행하거나 컴파일하지 않습니다. 선택 가능한 26개 언어의 모든 조합에 유료 AI 호출을 반복하지는 않았습니다. 일반 테스트와 CI는 유료 API를 호출하지 않습니다. Docker 이미지의 실제 실행은 별도로 검증하지 않았습니다. 테스트용 DB와 실패 추적은 Git에서 제외한 `artifacts/`, `test-results/`에 저장합니다. 공개 가능한 합성 데이터의 화면은 `docs/images/`, 성능 원시 값과 압축 추적은 `reports/`에 보존합니다.

## 모델 선택 후속 검증 — 2026-09-14

- 검토 기본값을 Luna medium으로 변경했습니다. 기존 16개 사례를 두 번 실행해 32/32 판정과 104/104 기준이 일치했고 제공자/검증 실패는 없었습니다. `/quality`도 이 결과를 표시합니다.
- 생성은 세 모델 각각 12회, 총 36회 호출했습니다. Sol 11회, Terra 12회, Luna 12회가 구조 검증을 통과했습니다. Sol의 결과 미수신 1회도 원문 보고서에 보존했습니다. 처음 인프라 주제의 길이 초과는 API 호출 전 fixture 오류였으며 모델 오류와 구분했습니다.
- 반례 10개를 해시로 고정한 일부 코드로 확인했습니다. 정성 검토와 일부 실행 검증이며, 모든 생성 코드가 실행 검증을 통과했다고 표현하지 않습니다. Sol에도 결함이 있어 가격과 품질의 일률적인 관계를 주장하지 않습니다. 생성은 비교 근거 부족으로 Sol을 유지합니다.
- 이번 후속 작업의 유료 호출은 총 68회(검토 32 + 생성 36), 운영 DB 쓰기 0회입니다. 앞의 저장 경합 검증에서 기록한 유료 호출 0회와 구분합니다.
- 전체 단위/DB 재실행은 64개 통과, 기존 모델 문자열을 기대하던 테스트 1개 실패였습니다. 기대값을 평가로 확정된 Luna로 변경하고 해당 테스트 파일과 평가 파일의 8개 테스트를 다시 실행해 모두 통과했습니다. DB 경합 테스트는 코드 변경 없이 전체 실행에서 통과했습니다. 포맷, 정적 검사, 타입, 미사용 코드 검사와 프로덕션 빌드도 다시 확인했습니다.

원문, 비용, 한계와 선택 근거는 [engineering.md](engineering.md)의 모델 선택 절과 [판단 보고서](../reports/ai-model-decision.json)에 있습니다. 이전 브라우저 42개 검증은 저장 안정성 개선에 대한 기록이며 이번 모델 평가의 정확도 근거로 사용하지 않습니다.
