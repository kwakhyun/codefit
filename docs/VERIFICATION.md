# 검증 기록

## 최신 검증 요약 — 2026-09-18

이번 실행은 전체 화면과 핵심 기능을 검토해 달라는 요청에 따라 진행했다. 현재 구성은 코딩 문제 24개, 입문 미션 29개, 5개 서비스 분야다. [UI 변경과 실제 화면](design/release-ui-review.md)에 문제, 영향과 구현 위치를 정리했다. 아래 이전 기록은 각 실행 당시의 기능/데이터 규모이며 현재 결과와 합산하지 않는다.

- **단위 및 SQLite: 166개 통과, PostgreSQL 23개 건너뜀**(2.64초). 로컬에 테스트용 PostgreSQL/실행 중 Docker가 없어 DB 변수를 설정하지 않았다. 운영 DB로 대체하지 않았다. GitHub Actions는 별도 PostgreSQL 16 서비스에서 같은 계약을 실행하도록 구성되어 있으며 이 로컬 결과에 CI 결과를 포함하지 않는다.
- **전체 브라우저: 88개 시나리오 × 3개 브라우저 = 264개 실행, 261개 통과, 3개 실패**(18.0분). 실패는 모두 같은 실습 검사에서 삭제된 안내 문구를 기대한 단언이었다. 기대값을 현재의 빈 초기 기록으로 수정했으며 앱 오류를 감추기 위해 검사 자체를 제거하지 않았다.
- **최종 빌드 후 영향 범위 재검증: 10개 시나리오 × 3개 브라우저 = 30개 모두 통과**(2.7분). 위 실패 3개, 로그인 안내, 가이드 선택/통신/키보드 조작, 새 실습 기본 축소 상태, 11개 공개 화면 계열과 프로젝트 질문/결과를 포함한다. 전체 실행과 별도 실행이며 294개가 한 번에 통과했다고 표현하지 않는다. 미해결 테스트 실패는 없다.
- 전체 핵심 흐름에는 29개 입문 실습, AI 코드 분석과 실행, 문제 검색, 북마크, 힌트/정답, 자동 저장, 다중 탭 충돌, 오프라인 복구, 제출본 복원, 백업, 계정 격리/프로필/로그아웃, 사용량 한도, 프로젝트 질문/평가/삭제, 가이드, 음성 입력 이벤트가 포함됐다. AI 응답은 모의 데이터, 로그인은 격리 DB의 테스트 세션으로 검사했다.
- **API 통합 검사 통과**: 공개 진입, 사용자 격리, 입력/Origin 검사, 저장, 힌트/정답, 백업 복원과 생성 로그인 제한을 격리 서버에서 확인했다. 최종 프로덕션 빌드와 TypeScript, ESLint, Prettier, Knip 및 문서 로컬 링크 검사도 통과했다.
- UI는 320/390/768px 가로 넘침과 390px axe WCAG 2 A/AA 및 2.1 AA 태그를 검사했다. 데스크톱/모바일 캡처를 직접 보고 가이드의 답안 가림과 메뉴 정렬을 수정했고, 별도 브라우저에서 선택 메뉴의 키보드 열기/선택을 조작했다. 자동 접근성 검사, 화면 시각 검토, 키보드 조작을 구분한다. 실제 휴대폰과 스크린 리더 청취는 검사하지 않았다.
- 로컬 로그인이 비활성인 이유는 OAuth 환경 변수 미설정이었다. 3010 사용자 미리보기와 3012 자동 테스트 서버를 분리하고 로컬 로그인 안내와 운영 링크를 추가했다. 운영 workspace의 제공자 `google`, `github` 활성 상태(HTTP 200)는 읽기만 확인했다. 실제 제공자 본인 인증/콜백은 이번에 다시 수행하지 않았다.
- 환경: Apple M2/16GB, macOS 26.6.2, Node 22.21.0, Next 16.3.4 프로덕션 빌드, Chromium 153.0.8010.12/Firefox 155.0/WebKit 26.6. 별도 SQLite, 로컬 네트워크, CPU/네트워크 감속 없음. 1회 전체 실행과 최종 영향 범위 1회 재실행이다. 소요 시간은 테스트 실행 시간이며 서비스 성능 또는 실사용자 지표가 아니다.
- 이번 검증의 유료 AI 호출과 운영 DB 쓰기는 0회다. 실제 음성 인식, 모델 품질 재평가와 부하/성능 비교는 범위에 포함하지 않았다. 원본은 로컬 `artifacts/full-unit.log`, `artifacts/full-e2e.log`, `artifacts/release-full-run/`, `artifacts/release-targeted.log`, `artifacts/ui-refresh/`에 남긴다. 현재 README에는 서비스 소개, 모델/한도와 기록 보관 범위를 반영했다.

## 화이트 실습 앱, 선택형 이유와 음성 입력 — 2026-09-18

[화면 구성과 구현 근거](beginner-training.md#서비스형-실습-화면과-음성-입력--2026-09-18)에 서비스별 UI, 처음 화면 조작과 관찰 기록의 분리, 선택 입력, 음성 처리와 실제 화면을 정리했다.

- 전체 단위/SQLite **124개 통과, PostgreSQL 21개 미실행**. 아홉 미션 모두 이유를 비워도 유효한 저장/완료 기록이 되고, 예상 선택과 동작 검사 등 나머지 조건은 필요한지 확인했다. 저장소 구현과 DB 구조는 변경하지 않았다.
- 프로덕션 빌드에서 입문, 코드 이해, 상황 그림과 신규 실습/음성 입력 **28개 시나리오 × Chromium/Firefox/WebKit = 84개 모두 통과**했다(5.6분). 아홉 미션의 조작/수정/완료, 초안 저장과 재진입, 오프라인/충돌/복구, 기존 AI 지연 응답, 새로운 빈 이유 저장, 우측 답안 배치, 자유 조작을 관찰 근거로 사용하지 않는 동작을 포함한다.
- 마지막 글자 크기와 안내 문구 수정 후 다시 빌드해 신규 **4개 시나리오 × 세 브라우저 = 12개 모두 통과**했다(56.0초). 위 84개와 별도 실행이며 합산하지 않는다. 최종 빌드, TypeScript, ESLint, 미사용 코드와 변경 파일의 포맷 검사를 통과했다.
- 320/390px에서 가로 넘침을 검사했고, 일곱 앱 유형의 390px 화면에 axe WCAG 2 A/AA 및 2.1 AA 검사를 적용했다. 자동 검사에서 상태 아이콘의 잘못된 ARIA 속성을 찾아 역할을 수정한 뒤 위 프로덕션 실행에서 통과했다. 실제 화면 검토에서는 쇼핑몰 가격용 CSS 클래스가 앱 전체에 적용되던 글자 크기 문제를 발견해 분리했다.
- 음성 자동 검증은 모의 SpeechRecognition 이벤트를 주입했다. 직접 타이핑 보존, 중간 인식 미저장, 확정 결과 중복 방지, 마이크 권한 거절, 종료 뒤 포커스 복귀, 화면을 떠난 뒤 늦은 인식 결과 무시, 미지원 브라우저의 직접 입력과 `microphone=(self)` 응답 헤더를 확인했다. 실제 사용자 음성이나 마이크는 사용하지 않았고 인식 제공자 연결/한국어 정확도는 검증하지 않았다.
- 개발 모드의 첫 신규 검사 4개 중 2개가 실패했다. 하나는 위 ARIA 문제였고, 다른 하나는 첫 게스트 진입의 연습실 불일치 응답으로 입력 화면에 도달하지 못한 경우였다. 후자는 음성 API 실패로 해석하지 않으며, 관련 계정 검사를 제거하지 않고 동일 직접 진입을 프로덕션의 세 브라우저에서 통과했다. 개발 모드의 초기 세션 요청 경합은 별도 조사 대상이다.
- 실행 환경: macOS 26.6.2/Apple M2/16GB, Node 22.21.0, Next 16.3.4, Chromium 153.0.8010.12/Firefox 155.0/WebKit 26.6. 별도의 임시 SQLite와 기본 문제 24개/입문 미션 9개, CPU/네트워크 감속 없는 로컬 조건이다. 성능 전후 비교, 실제 모바일 기기, 스크린 리더 청취와 학습 효과 측정은 수행하지 않았다. 화면 캡처는 `docs/images/sample-*.png`, 전체 보고서는 로컬 `artifacts/simulation-validation/`에 보관한다.
- 유료 AI 및 외부 음성 인식 호출, 운영 DB 쓰기, 커밋, 푸시와 배포는 수행하지 않았다. 음성 인식은 브라우저 지원에 의존하며, 미지원 환경에서는 직접 입력을 안내한다. 서비스 서버가 음성을 저장하지 않는다는 사실과 브라우저 제공자의 음성 처리 정책을 구분해 UI/개인정보 안내에 명시했다.

## 핏 마스코트와 AI 시작 가이드 — 2026-09-18

[캐릭터 기획, 구현 흐름과 실제 화면](design/fit-start-guide.md)에 선택 근거와 제한을 정리했다. 흑백 터미널 캐릭터 ‘핏’을 제작하고 우측 하단 가이드에 적용했다. 개발 경험, 목표와 시간을 세 단계로 선택하면 실제 미션 하나를 추천하고 후속 질문을 받을 수 있다. 기본 모델은 `gpt-5.6-luna`이며 문제 생성/풀이 검토 모델은 변경하지 않았다.

- 전체 단위/SQLite **124개 통과, PostgreSQL 21개 미실행**. 신규 12개는 추천 후보/시간, 입력 검증, 구조화 응답과 허용 ID, 소유자, 사용량 및 공급자 실패 처리를 확인한다. 이번에는 격리 PostgreSQL을 구성하지 않았으며 기존 사용량 저장소 계약을 재사용했다.
- 최종 프로덕션 빌드에서 신규 가이드와 기존 탐색 회귀 **10개 시나리오 × Chromium/Firefox/WebKit = 30개 모두 통과**했다(1.8분). 최초 방문의 무요청, 안내 숨김, 키보드 열기/Escape/포커스 복귀, 단계 선택, 미션 이동, 질문 취소와 늦은 응답 무시, 네트워크 오류 뒤 입력 보존/재전송, 계정 전환 초기화, 개인 초안 이어하기, 필터와 앵커 복원을 확인했다.
- 모바일 320/390px의 가로 넘침과 대화 스크롤을 검사했다. axe WCAG A/AA 자동 검사와 Playwright 입력 이벤트를 이용한 조작 검사는 구분한다. 로컬 브라우저 화면 및 캡처를 직접 검토했지만 실제 휴대폰의 가상 키보드와 스크린 리더 청취는 검사하지 않았다.
- 환경: macOS 26.6.2/Apple M2/16GB, Node 22.21.0, Next 16.3.4 프로덕션 빌드, Chromium 153.0.8010.12/Firefox 155.0/WebKit 26.6. 운영과 분리된 임시 SQLite, 기본 문제 24개와 입문 미션 9개를 사용했다. CPU/네트워크 감속 없는 로컬 기능 검사이며 성능 비교나 사용자 전환율 실험이 아니다.
- TypeScript, ESLint, 미사용 코드 검사와 프로덕션 빌드를 통과했다. AI 대화는 고정 모의 응답으로, 키 미설정 시 기본 추천은 실제 서버 경로로 검증했다. 서비스의 외부 유료 AI 호출과 운영 DB 쓰기는 **0회**이며 실제 모델의 추천 품질을 평가한 결과가 아니다. 마스코트는 별도의 내장 이미지 생성 도구로 제작했다.
- 대화는 탭 메모리에만 보관하고 다시 열 때 계정을 확인한다. 개인/접속망/공용 AI 한도를 원자적으로 적용하고, AI 없이 추천받는 경로와 실패 시 기본 추천을 제공한다. 응답 유실 후 수동 재요청의 중복 비용과 이미 시작된 호출 비용의 취소는 보장하지 않는다. 커밋, 푸시와 배포는 수행하지 않았다.

## 로고와 파비콘 개편 — 2026-09-18

후속 색상 요청에 따라 C와 조각의 형태를 유지하고 검은 배경/흰색 심볼로 교체했다. 최종 흑백 파일로 아래 36개 브라우저 조합을 다시 통과했으며, 크기별 비교와 실제 화면 캡처도 갱신했다. 색상 변경 단계에서는 애플리케이션 코드를 수정하지 않았다.

[기획, 적용 파일과 실제 화면](design/logo-refresh.md)에 정리했다. 새 C 심볼을 공통 헤더, README, 브라우저 및 Apple 아이콘에 적용하고 모바일 상단에 홈 아이콘 링크를 추가했다. Next.js 개발 서버와 격리 SQLite에서 Chromium/Firefox/WebKit × 1280/390/320px × 홈/입문/코드 분석/로그인 **36개 조합을 통과**했다. 이미지 로딩, 가로 넘침, 링크 이름, 아이콘 메타데이터와 모바일 키보드 홈 이동을 확인했다. 최초 ICO의 RGB 형식을 Next.js가 거절해 RGBA로 고친 뒤 최종 파일로 재검증했다. 수정 TSX ESLint와 프로젝트 TypeScript 검사를 통과했다. 실제 휴대폰 설치와 전체 기능 회귀 검사는 하지 않았으며, 운영 배포도 수행하지 않았다.

## 공통 용어, 단계별 그림과 예제 앱 화면 — 2026-09-18

### 확인한 동작

아홉 미션을 예상 작성부터 문제 재현, 불완전한 수정안 비교, 각 동작 검사, 응용과 완료 후 새로고침 복원까지 실행했다. 코드 입력이나 AI 호출 없이 끝낼 수 있다. 단계별 힌트, 기록 내보내기, 관찰 초기화 후 복구, 모바일 입력과 키보드 이동도 확인했다.

두 탭의 서로 다른 기록과 재충돌, 충돌 해결 중 새 입력, 오프라인 작성 후 복귀와 다른 게스트의 기록 격리를 검사했다. 늦은 AI 응답은 현재 입력을 보존하며, 같은 입력의 실패 재시도는 같은 ID를 쓰고 변경된 입력은 새 ID를 쓴다. 서버에서 잘못된 미션 기록, 워크스페이스 불일치와 근거 없는 AI 요청을 거절한다.

axe WCAG 2 A/AA 및 2.1 AA 자동 검사와 Playwright의 키보드/포커스 검사를 구분한다. 별도로 실제 인앱 브라우저에서 데스크톱과 모바일 화면, 생성 창 열기/닫기와 콘솔 오류를 확인했다. 스크린 리더 수동 청취와 학습자 사용성 실험은 하지 않았다. AI 문장 품질과 장기 학습 효과도 아직 측정하지 않았다.

### 발견한 문제와 수정

첫 전체 회귀는 **118개 통과, 5개 실패**였다(11.7분). 메인 문구 변경으로 기존 계정 테스트 3개가 오래된 제목을 찾았고 선택자를 갱신했다. Firefox의 배너 애니메이션에서 글자 대비가 낮아져 투명도 전환을 제거했다. WebKit에서는 메모 변경 후 AI 재시도 ID 검사 한 건이 실패했다. 별도 5회 재현에서는 통과했지만, 전환 제목에 중복된 지연 포커스가 있음을 확인했다. 포커스를 React의 화면 반영 시점에 한 번만 처리하고 메모 값과 초점 검사를 추가했다.

**조작 검사**: Playwright 입력 이벤트로 단계 버튼의 키보드 활성화와 포커스 이동, 메모 입력, 충돌 비교와 복원/취소를 확인했다. agent-browser로 실제 로컬 화면을 열어 렌더링과 콘솔 오류를 확인하고 데스크톱/모바일 스크린샷을 직접 검토했다. 스크린 리더를 사용한 수동 청취 검사는 하지 않았다.

### 검사 중 수정한 점과 남은 한계

- 최초 백업 검사 429는 이전 테스트의 접속망 가져오기 한도가 남아 있었기 때문이다. 제한을 제거하는 제품 변경 없이 과거 테스트 DB를 보존하고 새 테스트 DB에서 통과했다.
- 새 초기화/오류 테스트가 모든 `role=alert`를 선택하면서 Monaco와 Next.js의 숨은 알림까지 매칭했다. 실제 `.workspace-error`로 범위를 좁혀 테스트를 수정했다. 이 실패를 제품 데이터 유실로 해석하지 않는다.
- 정답 공개와 제출본 복원, 초기화 안내에 메모 보존/교체 범위를 명시했다. 시작 코드 초기화는 메모를 유지한다.
- 실제 AI 첫 검사 13건은 예상과 8건 일치, 메모를 보완한 참고 6건은 5건 일치했다. 오류 시작 코드 6건과 지시문 공격 1건은 모두 거절됐다. 참고 코드 자체는 자동 테스트를 통과해도 설명 누락으로 AI 리뷰에서 거절될 수 있다. 세부 사유와 비용은 [설계 문서](engineering.md#실제-ai-검토에서-발견한-문제)와 원본 보고서에 기록했다. 일반 리뷰의 기존 평가 수치를 인수인계 정확도로 재사용하지 않는다.
- 변형 과제는 코드 구조와 상황을 바꾸되 함수 계약을 공유하는 제한된 재훈련이다. 7일 경계는 가상 날짜와 제출 기록으로 검증했으며 실제 7일간 학습 효과를 관찰하지 않았다.
