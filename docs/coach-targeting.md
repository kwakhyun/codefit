# 학습자의 설명을 검증하는 코칭

예측한 값이 맞아도 이유가 틀릴 수 있다. 기존 코칭은 맞힌 결과를 다시 설명하거나 다른 경계 조건을 제안하면서, 학습자가 명시적으로 적은 잘못된 주장을 놓치기도 했다. `coach.4.1`은 전체 과제 계약과 설명을 함께 읽고 그 주장을 검증할 질문과 비교 실험을 제안한다.

## 제품 동작

- 새 AI 응답에는 `focus.learnerQuote`와 `focus.goal`이 필수다. 인용문은 예측 이유의 연속된 원문이어야 하며, 서버가 공백뿐인 인용과 원문에 없는 인용을 거절한다. 관련 기술적 설명이 없는 경우 인용은 `null`일 수 있다. 인용의 존재만으로 해석의 정확성을 보장하지는 않는다.
- 화면에 질문 당시의 설명과 확인할 점을 표시한다. 인용문은 HTML로 실행하지 않는다. 질문 이후 코드나 실행 근거가 바뀌면 기존 안내를 유지한다. 저장과 문서 내보내기에도 인용과 목적을 포함하며, 새 필드가 없는 옛 코칭 결과도 읽을 수 있다.
- AI에는 기본 계약뿐 아니라 핵심 수정과 확장 요구사항도 전달한다. 예측 값과 이유를 따로 검토하고, 질문·확인할 점·실험식이 같은 주장을 다루도록 지시한다. 올바른 이유에서는 오류를 만들어 내지 않고 미확인 경계를 탐색한다.
- 실험식은 사용자가 확인·편집한 뒤 명시적으로 실행한다. 원본과 수정 코드에서 각각 새로운 브라우저 Worker/QuickJS 환경으로 실행한다. 서버에서 사용자 코드를 실행하거나 AI 제안을 자동 실행하는 기능은 추가하지 않았다.

## 실제 모델 비교

개발자가 작성한 오해 6개와 올바른 설명 대조군 2개를 사용했다. 오해마다 참고 구현에 해당 오류 하나만 넣은 변형을 만들고, 구별 가능한 입력을 실제 실행으로 사전 확인했다. 변형 코드·목표 라벨·사전 확인식은 모델에 전달하지 않았다. 세 실행의 전체 입력 해시는 같으며, 모두 확장된 계약을 사용했다.

| 프롬프트  | 목표 오류를 구분한 실험 | 원본에서도 실행 가능한 목표 실험 | 발견 사항                                                          |
| --------- | ----------------------- | -------------------------------- | ------------------------------------------------------------------ |
| coach.3   | 5/6                     | 5/6                              | dispose 이후 새 load 호출에 관한 설명을 놓치고 요청 순서만 확인    |
| coach.4   | 6/6                     | 5/6                              | 재시도 실험이 원본의 undefined 반환을 그대로 담아 직렬화 오류 발생 |
| coach.4.1 | 6/6                     | 6/6                              | 목표 오류를 구분하고 원본에서도 관찰 가능한 값을 반환              |

문자열 페이지 변환, 실패한 작업 재시도, 잘못된 PORT 형식, 빈 DEBUG 문자열, dispose 이후 새 작업 호출, Promise 거절 전파를 다뤘다. 최종 응답의 두 대조군은 기존의 정상 동작을 오류로 단정하지 않았다. 이는 개발 에이전트의 정성 검토이며 독립 판정이 아니다.

기존 진단 사례 8개도 중간·최종 프롬프트로 다시 호출했다. 중간 응답에서는 “같은 검색어”라고 설명하면서 서로 다른 문자열을 넣은 실험과 재시도 실험의 undefined 직렬화 오류를 발견했다. 최종 응답은 같은 검색어를 공유 변수로 재사용하고 반환 상태·호출 횟수를 관찰하여 두 문제를 해결했다.

**남은 실패도 있다.** 최종 `inconsistent-client-observation` 직접 모델 호출은 원본과 맞지 않는 `[2,3]` 보고의 모순을 지적하지 않고 다른 경계 실험을 제안했다. 실제 제품의 코칭 HTTP API는 이 입력을 고정된 원본 결과와 비교해 유료 호출 전에 거절한다. 모델 자체의 출처 검증이 완전해졌다고 해석하지 않는다. 인용문이 원문에 있거나 실험이 실행된다는 사실도 질문의 교육적 적절성을 증명하지 않는다.

## 검증과 재현

- 변경 전·중간·최종 실제 AI 호출은 **40회**, 기록된 토큰 단가 기준 추정 비용은 **$0.0436992**다. 실제 청구액이 아니다. 합성 코드와 설명만 사용했다. 최종 프롬프트 호출은 16회이며 새로 숨겨 둔 독립 평가셋이 아니다.
- 최종 응답으로 생성한 실험은 목표 진단 22회와 기존 진단 16회, 합계 **38회 모두 값 반환**했다. 현재 실행기로 38회를 다시 실행하여 저장된 결과와 일치함을 확인했다. 사전 변형 검증을 생성 실험 수에 합산하지 않았다.
- 관련 단위 검사 **58개 통과**: 코칭 공급자·HTTP·훈련·실험 4개 파일 56개, 기존 초안 왕복/문서 내보내기 2개. 나머지 초안 검사 20개는 미선택했다.
- 관련 브라우저 시나리오는 **12개 통과**: 새 인용·복원·옛 응답 호환 3개, 기존 AI 실험 가져오기·오프라인/늦은 응답·동일 요청 재시도 9개. Chromium, Firefox, WebKit에서 격리 SQLite와 모의 AI 응답을 사용했다. 최초 새 테스트 3개는 재요청 버튼 이름을 초기 버튼 이름으로 찾는 테스트 오류로 실패했고, 선택기를 수정한 뒤 최종 프로덕션 빌드에서 세 브라우저를 재검사했다. 실패 횟수와 재실행을 별도 성공 사례로 합산하지 않았다.
- 390px 가로 넘침과 axe 자동 접근성 검사를 통과했고 `artifacts/coaching-focus-mobile.png`를 직접 검토했다. 실물 기기·사람의 스크린 리더 검사는 아니다. TypeScript 포함 프로덕션 빌드와 관련 ESLint·Prettier를 확인했다. 전체 테스트·운영 DB 작업·커밋·배포는 하지 않았다.

비용 없이 원본 해시와 최종 실험을 재검사하고 집계 보고서를 생성한다.

```sh
node --import tsx scripts/summarize-coach-targeting.ts
```

현재 프롬프트나 응답 스키마가 최종 호출 당시와 다르면 위 검사는 중단한다. 현재 프롬프트를 실제 모델로 다시 평가하려면 다음 명령을 사용한다. 각각 8회 유료 호출이며 `--live`를 생략하면 계획만 출력한다.

```sh
node --env-file=.env.local --import tsx scripts/evaluate-coach-targeting.ts --live
node --env-file=.env.local --import tsx scripts/evaluate-understanding-coach.ts --suite diagnostic --live
```

[집계와 원문 해시](../reports/coach-targeting-reliability.json)에 모든 단계의 응답을 연결했다. 집계 스크립트의 경로는 이번 비교 실행에 고정돼 있다. 새 평가 결과는 해당 비교 대상과 검토 기록을 갱신한 뒤 집계해야 한다. 독립 평가자 0명, 실제 학습 연구 참가자 0명이며 SOTA 또는 학습 효과 입증 자료로 사용하지 않는다.
