# 프로젝트 점검 근거와 수정 검증 기록

프로젝트 점검 화면에서 질문별 근거의 출처를 구분하고, 특정 항목의 수정 요청을 작성하며, 수정 전후의 테스트 관찰을 기록한다. 이 기능에는 추가 AI 호출이 없다.

## 근거의 범위

- **코드 위치 확인**: 질문이 공개 자료를 근거로 하며 인용이 저장된 커밋의 수집 코드와 일치한다. 전체 호출 경로나 실행 결과가 검증되었다는 의미는 아니다.
- **작성자 설명 근거 / 공개 화면 근거**: 해당 자료가 질문의 출처이며 소스 구현을 확인하지 않았다.
- **코드 근거 확인 필요**: 출처가 미확인이거나 수집한 코드와 인용이 일치하지 않는다. 임의의 원본 링크를 만들지 않는다.
- 파일 수와 부분 발췌 수, 수집 줄 수, 파일 목록의 잘림을 표시한다. 수집률을 보안 점수나 안전 판정으로 사용하지 않는다.

AI 수정 요청에는 원본 커밋과 검증된 코드 링크, 질문, AI 피드백, 사용자 기록, 미확인 범위를 넣는다. 자료는 JSON으로 구분하고 참고 자료의 지시문을 따르지 않도록 명시한다. 먼저 실제 문제 여부를 확인하고 필요할 때 최소 수정하도록 요청한다. 이는 외부 AI의 동작을 보증하는 보안 경계가 아니다.

## 수정 전후 기록

`practice.tasks[].verification`은 선택 필드이므로 기존 기록과 백업도 읽을 수 있다. 기존 소유자 권한, 낙관적 동시성, 저장과 백업 복구 경로를 사용한다. 필드 크기 제한은 실행 방법 300자, 각 단계 근거 600자이다.

| 입력                                         | 표시                         |
| -------------------------------------------- | ---------------------------- |
| 모든 단계 미실행 또는 기존 기록              | 테스트 미실행                |
| 수정 후 실패                                 | 수정 후 실패 기록            |
| 수정 전 또는 수정만 되돌린 사본에서 통과     | 결함 구별 여부 확인 필요     |
| 단계, 실행 방법, 실제 근거 중 누락           | 검증 기록 부족               |
| 같은 테스트의 실패 → 통과 → 실패와 근거 작성 | 재현 패턴 기록됨 (자기 기록) |

입력 도중의 불완전한 기록도 저장할 수 있다. 어떤 입력도 자동 검증이나 취약점 해결 판정으로 승격하지 않는다. 코드를 실행하지 않으며, 테스트 로그의 진위, 세 실행 환경의 동일성, 실패 원인도 자동 확인하지 않는다. 수정만 되돌리는 작업은 원본 작업 디렉터리를 덮어쓰지 않는 별도 사본에서 하도록 안내한다.

## 참고 설계와 출처

[Iron Laws](https://github.com/JinHo-von-Choi/iron-laws/tree/fd746b425dd566569b6bd4009ab04efef8afb0f6)의 검사 공백 표시, 근거를 포함한 수정 요청, 원본/수정본/수정 복원본의 회귀시험 흐름을 참고했다. 검토 기준 커밋은 `fd746b425dd566569b6bd4009ab04efef8afb0f6`이다.

참고 구현은 `src/iron_laws/core/ledger.py`, `reporters/prompt.py`, `verify/regression.py`, `evidence/verifier.py`와 관련 문서다. 원본은 MIT License, Copyright (c) 2026 Jinho Von Choi (최진호)이다. 코드핏 구현은 기존 TypeScript 데이터 모델에 맞춰 작성했으며 해당 Python 구현이나 규칙 엔진을 포함하거나 실행하지 않는다.

## 검증

- 단위 테스트: 인용 불일치, 비코드 출처, 부분 수집, 기록 누락, 수정 후 실패, 결함을 구별하지 못하는 테스트, 사용자 기록 표시, 다국어 입력 크기.
- 저장 테스트: 소유자 권한, 충돌, 기존 학습 기록 보존, 새 필드의 저장과 백업 복구.
- 브라우저 테스트: 데스크톱과 모바일에서 원본 링크, 복사와 수동 복사 대안, 기록 저장 후 새로고침, 접근성과 가로 넘침.

검증에는 합성 자료를 사용한다. 실제 저장소의 결함 탐지 정확도나 사용자 입력의 진위를 측정하는 테스트는 아니다.
