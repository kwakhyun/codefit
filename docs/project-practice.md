# 내 프로젝트로 연습

`/handoff`와 `/learn`은 기본으로 내 프로젝트 연습을 소개합니다. 기존 콘텐츠는 **샘플로 체험**에서 이용합니다. `/handoff?source=sample`, `/learn?source=sample`은 샘플을 바로 엽니다.

## 연결과 학습 흐름

1. `/project-practice?mode=code` 또는 `mode=service`에서 공개 소스 저장소(또는 GitHub PR)을 분석하거나 기존 기록을 선택합니다. 프로젝트 점검 상세에서도 두 연습으로 이동할 수 있습니다. `check` 쿼리로 기록을 지정합니다.
2. AI 전송 범위를 안내한 뒤 별도 동의 체크박스 없이 생성 버튼으로 코드 이해 3개와 서비스 동작 3개를 함께 만듭니다. 저장소 분석 1회와 연습 생성 1회가 각각 프로젝트 분석 한도에서 차감됩니다. 기존 분석을 선택하면 재수집하지 않습니다. 답변 평가 한도는 차감하지 않습니다.
3. 실제 코드 근거, 상황, 가정을 읽고 예상 결과를 선택합니다. 예상을 저장하면 모의 처리 과정과 해설을 표시합니다.
4. 내 말로 설명하거나 테스트 환경에서 확인한 결과를 기록하고 다음 상황으로 이동합니다. 세 상황을 완료하면 다른 연습 종류로 이어갈 수 있습니다.

## 근거와 한계

- 분석 당시 커밋과 선택한 파일 발췌가 기준입니다. 모든 파일이나 외부 의존성을 분석하지 않습니다. 저장소 변경은 새 분석에서 반영합니다.
- 생성된 각 문제의 근거는 실제 수집된 `path:Lnumber` 문자열인지 확인합니다. 답안 인덱스와 보기 범위도 검증합니다. 해설의 의미적 정확성을 자동으로 증명하지는 못합니다.
- 코드 이해는 정적 코드 읽기, 서비스 동작은 명시한 가정 아래의 교육용 모의 과정입니다. 실제 저장소를 실행하지 않고 외부 요청, 파일 수정, PR 작성도 하지 않습니다.
- 누락된 코드로 취약점이나 버그를 단정하지 않도록 생성 지침을 제한합니다. 실제 확인은 사용자의 로컬/테스트 환경에서 수행하도록 안내합니다.
- 기록 내용은 AI가 채점하지 않습니다. 완료 표시는 실습 흐름을 마쳤다는 뜻이며 실제 테스트 통과를 의미하지 않습니다.
- 비공개 저장소 연결은 지원하지 않습니다. 샘플 코드 훈련의 격리된 JavaScript 실행은 기존대로 별도 제공합니다.

## 저장과 API

`/api/project-check/[id]/practice`:

- GET: 현재 소유자의 생성 실습과 진행 기록. 생성 전에는 null.
- POST: `{}`. 두 종류의 연습을 한 작업으로 생성합니다. 같은 분석 기록의 중복 요청은 완료된 결과를 재사용하며 동시 요청은 409로 안내합니다.
- PATCH: `{ mode, revision, progress }`. 예상 선택, 확인 기록, 완료 상태를 저장합니다. 존재하지 않는 보기나 앞 단계 미완료 상태의 건너뛰기는 거부합니다. 변경 버전을 검사해 다른 탭의 기록을 덮어쓰지 않습니다.

결과는 `project-practice:<checkId>` 작업으로 서버에 저장합니다. 프로젝트 삭제 시 함께 삭제하며, 생성 도중 부모 프로젝트가 삭제되면 결과를 다시 만들지 않습니다. SQLite→PostgreSQL 이관에는 완료된 실습과 진행 기록을 포함한다. 개인 백업에 실습과 진행 기록을 포함하며, 가져오기 시 근거 코드와 단계 순서를 다시 검증합니다. 로그인 전 기록은 기존 방문자 쿠키, 로그인 후 기록은 계정 소유권을 따릅니다.

답변 선택과 완료는 즉시 서버 저장합니다. 자유 입력은 **기록 저장** 또는 다음 단계 버튼을 눌러 저장합니다. 생성 이후 학습에는 추가 AI 호출이 없습니다.

생성 요청이 실패해 해당 작업의 실패 상태를 확인한 경우 개인 분석 횟수와 방문자 네트워크 분석 횟수를 복원합니다. 과도한 재시도를 제한하기 위한 전역 호출 한도는 유지됩니다. 다른 사용량 초기화 구간에 영향을 주지 않도록 차감 당시 구간을 확인합니다.

실습 생성은 최대 105초 범위에서 서버가 진행합니다. 생성 중 화면을 이동했다면 같은 프로젝트에서 **저장된 기록 다시 불러오기**로 완료 결과를 확인할 수 있습니다. 서버 실행 환경이 종료되면 완료를 보장하지 않으며, 만료된 작업은 재시도할 수 있습니다.

## 홈에서 한 번에 시작

홈의 공개 저장소 링크 입력창은 프로젝트 분석과 실습 생성을 순서대로 진행합니다. 새 분석 1회와 생성 1회가 필요합니다. 두 번째 단계가 실패해도 이미 저장한 분석은 유지하며 같은 요청 ID로 재시도하면 완료된 단계는 다시 호출하지 않습니다. 서비스 점검실과 공간 선택 전 홈에서 바로 입력할 수 있습니다. AI 워크숍의 입력창은 프로젝트 AI 활용 학습으로 연결하고, 코딩 트레이닝 홈은 문제 풀이에 집중합니다.

프로젝트 분석, 맞춤 실습 생성, 코딩 문제 생성의 모델은 GPT-5.6 Sol을 기본으로 사용합니다. 생성용 환경 변수에 하위 모델을 지정해도 Sol로 적용하며, 명시적으로 지원하는 상위 모델인 GPT-6 Astra는 선택할 수 있습니다. 답변 평가와 코칭은 별도의 모델 설정을 사용합니다. 모델 간 품질 향상 효과를 비교 실험으로 입증했다는 의미는 아닙니다.

## 근거와 확인 문제 생성

프로젝트 실습은 요청별로 서버가 부여한 코드 구간 ID만 인용할 수 있다. 서버는 ID를 실제 발췌 줄로 변환하고 원본 스냅샷과 다시 대조한다. 질문 생성과 AI 활용 학습에도 같은 근거 계약을 적용한다.

정답 인덱스는 모델에 요청하지 않는다. 정답 문장과 오답 문장을 받아 서버에서 순서를 정하고 인덱스를 계산한다. 중복 선택지와 알 수 없는 근거는 저장 전에 거부한다. 생성 지침은 단순한 HTTP 상태 암기보다 재시도, 중복 부작용, 버전 충돌, 부분 실패와 복구처럼 여러 동작을 연결하는 상황을 우선한다.
